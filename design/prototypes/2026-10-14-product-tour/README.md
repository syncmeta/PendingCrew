# PendingCrew：产品介绍本身就是交互内容

本版取代上一版网站改版/旅行/研究三个虚构业务场景。保留上一版目录，不覆盖其状态。打开 `dist/index.html`，或以 `?embed=1` 嵌入网站。

网站顶部只保留品牌与介绍、工作方式、开始使用、文档四个入口，没有大标题、说明段落或场景选择器。介绍放在 Mac 窗口里的机组、消息、文档与阅读计划中：

- 认识 PendingCrew：产品定位、人/机长/成员的分工、为什么使用机组组织持续协作。
- 协作方式：原始需求、三层计划、唯一待人类收件箱、进展与计划的同源引用。
- 开始使用：围绕一个目标建立机组、明确要求、参与判断；文档包含正式文档和发行页入口。

阅读计划用于体验层级、状态、引用和答复，不是产品开发进度或真实运行任务。新增内容只保存到浏览器，网页不连接真实 agent。安装版本的功能和要求以正式文档/发行说明为准，网页呈现也包含本设计 session 已确认的目标交互。

## 原样式修正

只读核对 `Sources/Mac/Views/CrewColorBar.swift`，直接按其算法实现颜色：UInt64 FNV-1a（offset 1469598103934665603、prime 1099511628211）→ hue = hash % 360，HSV saturation 0.62、brightness 0.82。色条宽 5px、高 32px；自身占上半，第一父的色链递归压入下半，最后两段等高；防环、最多 8 个颜色。多父引用使用同一机组 ID 和第一父色链，不能因出现位置不同而重新配色。

父子关系：PendingCrew 下为认识 PendingCrew、协作方式；开始使用归协作方式，另在阅读入口借显。它的两处色条一致。外层消息活动流仍只显示机组；群聊和单聊列表只在消息 tab 内。

会话摘要原先是 inline span，宽度与省略规则不能生效。本版改为 block；同时给内容区和名称 flex 子项设置 min-width:0、受限宽度、overflow:hidden、white-space:nowrap、text-overflow:ellipsis，时间保留固定空间。拖动手柄位于栏内，避免它额外撑出 scrollWidth。桌面和手机用超长消息实际检查边界。

## 验收与发布包

`verify.cjs` 检查紧凑导航、产品内容、原色彩算法与谱系分段、多父一致、长预览省略与实际宽度、章节导航、文档/发行入口、原气泡样式、分栏折叠、三层计划、同源备注、人类答复联动、独立文件夹、重置、手机布局及嵌入模式。记录与截图在 `evidence/`。

发布包 `PendingCrew-Product-Tour.zip` 的根目录就是网页入口与静态资产，不依赖 CDN、npm 安装或服务端。后续可将目录放到已有网站，再用 iframe 引用 `index.html?embed=1`。本次未上传或发布网站，未改产品 Swift/Rust、共享计划、项目配置或根 README，未提交/推送、切分支或启动产品应用。
