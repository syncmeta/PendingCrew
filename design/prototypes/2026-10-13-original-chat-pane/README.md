# PendingCrew：在原 UI 上增加消息内会话选择

2026-10-13 最新纠正：前端继续沿用原设计和样式；外层 sidebar 保留机组列表。群聊、单聊的会话选择属于右侧「消息」tab，不属于外层 sidebar。此前 `folders-chat` 中把会话放在 sidebar 的方案被本版替代，文件原样留存。

入口：`index.html`；可编辑设计：`PendingCrew-OriginalChatPane.sketch`。33 个原生画板，起点「01 群聊」。浏览器和 Sketch 使用同一份图层与跳转目标。

## 消息 tab 内部

外层先选机组；右侧顶部仍为消息、Todo、文档、进展。只有消息 tab 内部拆为会话列表与聊天区域。

会话列表混排「本群」、成员私聊、该机组内的主题讨论群，按最近活动排序。显示稳定头像、名称、摘要和时间；群聊单聊不设 tab。选择会话不改变外层机组选中项。其他机组的内容先通过原 sidebar 选择所属机组。

聊天区域继续沿用当前头像、发送人、消息气泡、引用、时间、@ 筛选、附件与输入区。右上显示本群 Todo，右下显示成员；这两个面板按原来的上下结构组织，可以分别折叠。右上「收起侧面板」隐藏整块辅助栏，让聊天区域扩宽；再展开仍回到 Todo 在上、成员在下。

折叠动作只改变布局，不改变已选会话、未读、草稿、滚动或消息；产品中保存每个会话的面板状态，分隔尺寸沿用原 VSplitView 的可调整行为。窄窗口优先收起辅助栏；必要时会话列表用返回进入，但不把它挪回外层 sidebar。

主题群的成员与 Todo 归属需要明确：默认「本群」引用机组原有记录；私聊保留所属机组辅助信息。未来若主题群具备独立成员集合，面板要展示该 conversation 的范围与关联 Todo，不自动复制或建立另一份账本。原型目前显示相同示例集合，未实现实际范围过滤。

## PendingBot 群头像

只读参考源文件：`/Users/hey/Untitled/Pendingname/PendingBot/dev/apps/pendingbot/Sources/Components/GroupAvatar.swift`。

沿用白色圆底、灰色细边框、三枚互不重复 emoji 的三角布局，不采用成员照片拼图。用稳定 conversation ID 作为 seed；同一群在列表和详情使用同一头像，不依赖最近发言者、临时 session 或成员排序。

原型的 `pick()` 按该文件移植：从 1469598103934665603 开始，对 Unicode scalar 做 FNV-1a，乘 1099511628211 并保持 UInt64 溢出；从同一 48 个 glyph 中取三枚，随后用乘 6364136223846793005 加 1442695040888963407 的游标推进并去重。位置与字号按原来的 `r = size × 0.18`、字号 `size × 0.32`、三角偏移计算。群头像用原生 Oval 和独立文字图层，可编辑。

单聊用单枚头像，和群头像区分；原型单聊图案仅作示例，产品继续使用已有用户/agent 的头像来源与默认规则。

## 分组与结构化进展保留

上一轮确认的需求仍有效：消息、Todo、文档、进展分别有独立文件夹树，agent 能组织各自的分类；不由机组层级派生，也不因同名自动同步。

消息文件夹入口位于内层会话列表或聊天工具条，外层 sidebar 不出现内容文件夹。会话分类与消息引用分类是不同对象；Todo、文档、进展仍在各自 tab 内组织。移动仅改变归类，稳定 ID、源 Todo 编号、答复和跨视图引用保持有效。

进展继续展示目标、负责人、状态、下一步、内部步骤、依赖、检查项及产物；工作与步骤分别折叠，产物可跳到文档，源 Todo #20 打开 #20。文件夹树负责组织工作，步骤树负责描述工作，不合并为机组树。

接口需求延续上一版，但需要新增明确的 `Conversation(id, crewId, kind, title, participantIds, lastActivity, unread, avatarSeed)`。群会话应有稳定 ID 和 seed，私聊有明确接收对象；会话切换保存各自草稿与位置。辅助面板折叠状态属于 UI 偏好，不是 agent 的工作状态。本次仅保存设计需求，未向后端 session 发送消息，不能假定它已收到或实现。
