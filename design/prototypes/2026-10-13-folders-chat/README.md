# PendingCrew：微信式聊天、独立文件夹、结构化进展

本版依据 2026-10-13 的最新设计意见，在旧版旁另建目录，旧版及产品源码保留。

打开 `index.html` 看可点击预览，打开 `PendingCrew-FoldersChat.sketch` 编辑原生文字与图形。起点为「01 群聊」。28 个画板覆盖聊天、通讯录、Todo 答复、文档详情、进展多级折叠、分组及搜索。浏览器使用同一份图层坐标和连接，顶部选择器能直接查看各设计状态。

## 布局

- 左侧顶层只有通讯录和消息。通讯录保留机器、机组父子关系和多父引用；同一机组在不同父项出现时还是同一个机组。
- 消息是微信式最近活动列表：群聊和单聊混排，行里显示名称、来源机组、最后消息、时间和未读提示。没有群聊/单聊 tab。
- 选中机组后保留消息、Todo、文档、进展四个视图。点击成员进入同一列表里的单聊；标题显示私聊对象和所属机组，点击群聊行返回群聊。
- 聊天中心保留头像、发送人、气泡、时间、引用和输入区；右上是本群 Todo，右下是本群成员。私聊仍显示所属机组的 Todo 和成员，标题明确私聊目标。
- 文件夹展开在内容视图内；不把分类变成新的顶层导航，也不扩展成仪表盘。

## 独立文件夹

每个机组有四棵独立的文件夹树，分别属于消息、Todo、文档、进展。通讯录里的机组 DAG 与这些树是两个不同层次：选择机组决定内容归属，文件夹只决定该内容如何组织。

| 视图 | 示例文件夹 | 被组织的对象 |
| --- | --- | --- |
| 消息 | 实现讨论 / 验证讨论、界面讨论 | 消息或一段讨论的引用集合 |
| Todo | 首版验收 / 工具验收、前端设计 | 已存在的 Todo |
| 文档 | 验证记录 / 重连记录、设计说明 | 文档 |
| 进展 | 首版实现 / 检查点、界面迭代 | 结构化工作记录 |

agent 和人类都可新建、重命名、嵌套及移动分组，并把已有内容放入分组。分组不隐含指派、改变状态、创建任务或移动到其他机组。四棵树的名称和结构可以完全不同；不要根据同名文件夹自动同步。

采用主文件夹加可选引用的设计：一份内容只有一个稳定 ID，可放在一个主文件夹；其他文件夹可引用它，显示引用标记。Todo 的编号、账本、人类原文、答复链及源机组不因归类变化；右栏只是同一份 Todo 的缩略展示。消息原始时间线保留，分类用引用，避免破坏上下文。左侧会话列表的文件夹则组织会话，和群内消息分类区分开。

每个视图独立记住选中的文件夹、展开节点、滚动位置和搜索条件；切换机组后读取那个机组自己的位置。新内容未指定位置进入「未分组」，「全部」始终可找回。移动对话显示目的树与所选对象数量，确认后才改变主文件夹；拖动可作为同一动作的快捷方式。

文件夹菜单提供新建、重命名、移动、删除文件夹。删除空文件夹可直接完成；非空文件夹要明确把内容移到「未分组」，不会删除记录。详情菜单提供放入文件夹、移动、添加引用和移除引用。agent 做的分类变更能从记录详情查看，并可撤销。

## 结构化进展

工作记录展示标题、状态、负责人、目标、源 Todo、更新时间、下一步。内部是可独立折叠的步骤树，步骤有稳定 ID、负责人、状态、依赖、检查项、产物和更新时间。文件夹是组织这些工作的目录；步骤树是工作本身的结构，两者不要混为一棵树。

W12 示例包含「01 工具验收」和「02 检查点跟进」。点击工作标题折叠整个工作；点击步骤标题只折叠该步骤。点击产物打开文档，点击源 Todo 打开同一编号的完整原始记录，返回后保留当前位置。进展是结构化记录，不把聊天里的“已完成”自动当作已验收；检查项可以链接证据，等待人类、失败、暂停等状态都能明确展示。

未展开时显示一步摘要和子项数量；展开后按需要显示细节，不一次堆满所有日志。历史/冻结工作显示只读，缺失引用显示原 ID 与不可用原因，保留返回路径。

## 待实现接口交接

本 session 没有更改后端或产品 Swift。以下是设计需求，需和后端 session 明确协商，不能假定已经存在：

- `Folder(id, crewId, scope, parentId, name, order, revision)`，scope 为 message/todo/document/progress；目录不能循环，也不能跨 scope 设置父项。
- `Placement(contentId, folderId, kind)`，kind 为 primary/reference；稳定内容身份与分类关系分开。
- 分组的创建、重命名、移动、归类、引用、删除、撤销；agent 与人类使用一致语义，保留作者、时间及 revision，冲突不覆盖最新改动。
- `Progress(id, sourceTodoRef, owner, status, goal, nextAction, updatedAt)` 与 `Step(id, progressId, parentStepId, owner, status, dependencies, checks, artifacts)`；状态需要以实际数据为准。
- 会话列表包含群聊和单聊，用稳定 conversationId、crewId、participantIds、lastActivity、unread；草稿和滚动位置按会话保留，不能把私聊发到群聊。
- 空、加载、失败、只读、权限不足、引用失效、长标题和大量内容需要完整处理；窄窗口把右栏收成可展开面板，仍按上 Todo、下成员排序。

## 原型与验收边界

这是可点击的设计状态原型：文件夹名称、输入答复和消息都是预填示例；保存、移动、发送表现为画板跳转，不实际编辑或持久化业务数据。树的各展开/折叠状态可点击，Sketch 内文字和图层可编辑。拖动、自由输入、撤销、真实搜索和后端接口属于后续实现，不能把本原型当作这些功能已经完成。

`native-integrity.json` 记录 schema 约束检查、ID 唯一性、Flow 目标和起点；官方 sketchtool 导出 `exports/`。`browser-verification.json` 记录浏览器实测流程及边界检查。已经检查聊天和进展截图。Sketch.app 主程序缺失的问题未修复，所以不声称 Sketch.app 内原生播放已验证。
