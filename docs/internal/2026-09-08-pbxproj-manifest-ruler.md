# 给 pbxproj 生成加一条会红的尺子（2026-09-08）

<!-- doc-ref-base: 84f4f15 -->

本文里所有读数都在 `84f4f15` 这棵树上量的（本单开工时的 worktree HEAD，已是 main 的祖先）。
第七节那个「main 没有漂移」是唯一的例外，它量的是当时的 main `d20bccc`。

## 一句话

**派活时设想的那条尺子（落指纹文件）我推翻了 —— 它比仓库里已经有的那条弱，而且它瞄的那个量在这个仓库里原理上就测不出来。** 我改成补 CI 那条尺子够不到的地方，落了一条一直在跑的测试，并用三次变异证明它会红。

---

## 一、先验的那个前提：通过

派活要求「不验证就别往下做」。验了：

| 实验 | 结果 |
|---|---|
| 钉住的 2.46.0，删空重生成 ×3，比 sha | **三次逐字相同** |
| 和仓库里已提交的那份比 | **相同** —— 说明生成还与目录无关（我这个 worktree 路径 ≠ 当初提交它的地方） |

所以「天天假红然后被人关掉」的风险不成立。

## 二、但同一轮实验推翻了这一单的前提

**本机那份 2.45.4 和钉住的 2.46.0，对当前这份 `project.yml` 的输出逐字节相同（diff 0 行）。**

这不只是「造不出红样本」，它把问题的形状改了：

> **「谁跑的生成器」这件事在产物上不留任何痕迹 —— 不是我们还没想到办法，是字节一样，原理上就没有可测的量。**
> **而且它也不值得测：字节一样就等于没出事。**

派活里说「让绕过入口这件事在产物上留下可检测的痕迹」。可检测的痕迹只能靠**新写一份指纹**去人为制造，而那份指纹是可以手改的第二份真值 —— 裸跑之后顺手更新它就绿了。

## 三、更要紧的：仓库里已经有一条形状正确的尺子，而且更严

`.github/workflows/ci.yml` 的 **`project-drift`** job：

```yaml
- run: scripts/gen-project.sh --fetch          # 按 .xcodegen-version 装
- run: git diff --exit-code                    # 提交进来的 pbxproj 必须逐字等于重新生成的
```

它不可伪造（没有第二份真值可改），而且**它抓的东西严格多于指纹**。三种病对照：

| 病 | 指纹方案 | CI `project-drift` | 我落的这条测试 |
|---|---|---|---|
| 加了 Swift 文件没 regen（#490） | **绿（瞎）** —— pbxproj 一个字节没动，指纹当然对得上 | 红 | **红** |
| 手改 pbxproj | 红 | 红 | 绿（不查内容） |
| 用别的版本生成器跑出不同字节 | 红 | 红 | 绿（不查内容） |

**第一行是关键**：那是唯一一种「提交者自己能编、别人 clone 下来才炸」的错，而指纹方案对它完全瞎。派活里建议的方案，恰好在最需要它的那一格是绿的。

所以我不发明第二种判据（仓库里已有正确范式，照抄不另造），只补它够不到的地方。

## 四、那 CI 这条尺子够不到哪儿 —— 这才是真正的缺口

**它要 push 上 GitHub 才跑。而这个仓库的常态是本地 main 远远领先 origin。**

实测（开工时）：

```
origin/main: 09bf579  2026-09-07 15:18  release: prepare PendingCrew 0.1.27
local  main: 84f4f15  2026-09-08 18:17
未推送的提交数: 27
```

**今天一整天的活，CI 一眼都没看过。** 今天那四次裸跑正落在这个窗口里。

而本机这一侧：`scripts/release-gate.sh`（自称「发版闸门 / 合前基线」）和 `scripts/test-mac.sh` **都没有任何漂移检查**。所以缺口不是「没有尺子」，是**唯一那条完整的尺子挂在一道这个仓库平时不走的门后面**。

## 五、落了什么

`Tests/PendingCrewTests/ProjectFileManifestTests.swift` —— 判据：**磁盘上的每个 `.swift` 都必须在 pbxproj 里**。

- 跑在**普通的 `xcodebuild test` 里**，所以本机、闸门、CI 的 build-test job 全都带着它，不需要装 XcodeGen、不联网。
- 源码根**从 `project.yml` 现算**，不写死第二份名单（写死的那份会和 project.yml 各自漂，而漂掉的那天没有任何读数会报警）。
- 空转防护：两个集合任一少于 300 就直接判失效 —— 解析器一坏，两个集合都变空、差集为空、看起来全绿。

### 顺带发现：反方向那条断言**结构上不可能红**，所以我删了

我本来写了对称的第二条（pbxproj 引用了磁盘上没有的文件）。造红样本时发现它**永远轮不到发声**：

```
error: Build input file cannot be found: '.../ZZDanglingDecoy.swift'
```

`xcodebuild` 在编译阶段就停了，测试根本没跑到。**那件事编译器已经抓了，比测试更早、更响。** 留一条永远不会红的断言比不留更糟 —— 它看起来像覆盖，其实是空的。删掉，并把这次实验写进文件注释，免得下一个人「补全对称性」时再加回来。

## 六、造红：三次变异

| # | 变异 | 期望 | 实测 |
|---|---|---|---|
| A | 不动（现状） | 绿 | **Executed 6, 0 failures**（不是 Executed 0 的假绿） |
| B | 加一个 `.swift` 不 regen —— **就是今天那场事故的形状** | 红 | **红，且只红那一条**，报出文件名 + 修法 |
| C | 把 `sourcePaths` 短路成返回 `[]`（打断解析器） | 红 | **红** —— 空转防护和三条自检同时红，没有假绿 |

C 是专门为「删掉被测项不红 ≠ 它被测到了」补的：证明尺子坏掉时会红，不会静默变绿。

B 的红样本**贴近真实事故**：它就是「改了工程定义但没走入口」。至于派活里说的「用 2.45.4 裸跑一次」那个样本，**我没能造出来** —— 因为两版输出逐字节相同（第二节），那次裸跑在产物上没有任何差异可红。**这不是尺子漏了，是那件事本身没有后果。**

## 七、顺带量到的一个读数：main 现在没有漂移

在一棵一次性 worktree 上，对 `main`（`d20bccc`）跑了一遍 CI 那条判据：

```
✅ git diff --exit-code 通过：main 上提交的 pbxproj == 钉住的 2.46.0 生成出来的
```

**所以今天那四次裸跑没有留下任何损害。** 这和第二节对得上（两版输出相同）。

（那棵 worktree 已经 `worktree remove` 掉了 —— 建在 scratchpad 里的登记如果活得比目录久，就成了一条会骗人的登记。）

## 八、这条尺子抓不到什么（边界）

1. **同名文件在目录之间搬家**：集合按 basename 比，`A/Foo.swift` → `B/Foo.swift` 两边都不变 ⇒ 绿。重建完整路径要把 PBXGroup 整棵组树解出来，收益不值那份复杂度和噪音。
2. **手改 pbxproj 的内容**（改设置、改 build phase，不增删文件）⇒ 绿。归 CI 的 `project-drift`。
3. **用别的版本生成器跑出不同字节** ⇒ 绿。同样归 CI。
4. **有人裸跑之后又手动把产物弄"对"** —— 本条不查内容，无从判断。
5. **它只在 `xcodebuild test` 真的跑起来时才发声**。build 阶段就红的错（比如第五节那个）会挡在它前面。
6. `Fixtures/` 跳过（project.yml 明确 excludes，那份数据不入 git），所以放进 Fixtures 的 `.swift` 不被看住。

## 九、还差一步，我没做（附补丁）

**完整那条检查仍然只在 GitHub 上跑。** 建议把它接进 `scripts/release-gate.sh` —— 那是「合前基线」，是每笔落 main 都要穿的门。

我**没有动这个脚本**，原因是具体的、不是谨慎表演：**机长此刻正在跑发版闸门**（群里刚说「#125 我这就开始发版 —— 先跑闸门」）。`sh` 按字节偏移增量读脚本，改一个正在跑的脚本会让它读到半行、炸在不相干的行上。等这趟闸门跑完再接。

建议加在脚本**末尾**（在 `after_diff` 之后，才不会扰动读数 ④）：

```sh
echo "--- 工程漂移（pbxproj 是否 == 钉住的生成器产物）---"
if XCODEGEN= sh "$WT/scripts/gen-project.sh" --fetch >/dev/null 2>&1 \
   && git -C "$WT" diff --exit-code --stat -- PendingCrew.xcodeproj >/dev/null; then
  echo "  ✅ 无漂移"
else
  echo "  ❌ 有漂移：pbxproj 和 project.yml/源码对不上，或生成器版本不对"
  git -C "$WT" diff --stat -- PendingCrew.xcodeproj
fi
git -C "$WT" checkout -- PendingCrew.xcodeproj 2>/dev/null || true
```

（最后那行还原是必要的，也是安全的：`$WT` 是闸门自己建的一次性钉死 worktree，不是共享工作树。）
