# M4 public terminal custody and observation contract

Status: complete-module implementation draft. The root confirmed this is an existing M4 delivery requirement. Nothing below is advertised by today's Core12 normal executable. Public `session.inspect.screen` and `session.runnerItem` remain the currently implemented client surfaces. A read-only terminal is an intermediate integration state, not complete terminal delivery.

## Existing authority and runtime capability

Reuse existing `session.start`, `session.stop`, `session.resume`, `session.inspect` and scope/authentication. The client never owns the provider process or a second session ledger. No Codex-internal messaging or legacy Swift PTY/SessionDaemon authority is reintroduced. A runtime advertises controls only for an actually instantiated true PTY adapter. Structured Codex runner output is `runner`; it does not imply a PTY or authorize raw keyboard input. Claude through ACP still requires an actual interactive PTY. Missing native SDK/history/prompt/approval/Stop evidence remains an explicit gate.

A generation is a Core-issued opaque runtime identity bound to the current session and custody/native/helper chain. It changes on physical replacement/recovery. Claims and operations pin it; a stale generation is refused before effects. Claimed JSON actor or PID never confers authority. Existing IPC peer authentication or paired remote identity, current grants, crew/session scope and actual kernel/custody identity must all hold. Only a Human client can claim manual control; registered agents have no tool that grants it.

## Proposed public methods and events

- `session.terminal.inspect({sessionId,maxBytes?})` returns `{sessionId,generation,outputKind,controlCapabilities,screenSnapshot,byteCursor,truncated,exited}`. `outputKind` is `vt` or `runner`; unknown future vocabulary remains readable. `controlCapabilities` comes from the actual runtime, not static executor-name inference.
- `session.terminal.watch({sessionId,generation,afterCursor?})` starts a connection-owned bounded observation subscription. `session.terminalOutput` emits `{sessionId,generation,cursor,bytesBase64,truncated}`. Lost/gapped cursors require the current snapshot. UTF8 text, arbitrary PTY bytes and invalid encodings survive the codec. Observation has no native content/turn/completion authority.
- `session.terminal.claim({sessionId,generation,requestId})` explicitly requests exclusive Human manual custody and returns a lease bound to the authenticated principal, current connection and generation. Competing claims produce a typed conflict. Before a usable lease is issued, automatic native receipts/content are durably revoked and Core's acknowledgement is committed. Claiming cannot clear unknown outcomes or revive prior automatic input.
- `session.terminal.input({sessionId,generation,leaseId,requestId,bytesBase64})` validates exact lease/actor/scope/runtime, records immutable bounded bytes plus hash and prepared state, obtains durable manual revocation acknowledgement, then permits one physical write. A matching duplicate returns the saved disposition; a different payload under the same request ID is refused. Dispositions distinguish `prepared`, actual `written`/`acceptedByPty`, `unknown` and `suppressed`. A normal PTY write confirms only the exact bytes accepted by the kernel, possibly partially. It cannot establish consumption by the native application. Without a genuine reader ACK, no `consumed` state is permitted. Partial/interrupted writes become explicit unknown outcomes; neither the remainder nor the complete body is automatically written again.
- `session.terminal.resize({sessionId,generation,leaseId,requestId,rows,columns})` uses the same custody/idempotency path. Validation bounds geometry, and a confirmed result follows the actual PTY resize acknowledgement. It does not claim a native turn result.
- `session.terminal.release({sessionId,generation,leaseId,requestId})` relinquishes that connection's exclusive lease. It does not replay uncertain bytes or restore old automatic receipts. Explicit Human recovery/Resume can establish a fresh runtime admission; genuine native capability is still required for automatic operation.

The exact schemas and normal dispatcher methods freeze together after the production adapter, admission, persistence and stream backpressure routes are complete. A dedicated `session.terminal` capability must remain absent until those routes exist; the existing `orchestra` group continues to mean its currently supported session operations. Method constants alone do not advertise behavior.

## Durability, shutdown and observation bounds

Keep bytes losslessly encoded and frame-bounded. A proposed input/observation chunk limit64KiB permits base64 overhead within the existing1MiB public control frame; enforce the encoded total envelope bound as well. Native full-content admission separately needs the already recorded large-body codec/limit resolution. Streams have bounded rings and subscriber buffers, monotonically increasing cursors within a pinned generation, explicit truncation and cancellation. A slow/revoked client cannot hold Core shutdown or consume unbounded memory. Reconnect takes a new subscription and cannot blindly resume a manual lease.

Disconnect, remote revoke, runtime exit, Stop and generation replacement close lease admission. Any prepared but unconfirmed write becomes unknown; persistence and physical cleanup are separate obligations. Neither disconnect nor release resets the durable automatic revocation floor. Stop continues to settle/reap actual runtime descendants; `exited` derives from real process settlement, not an empty stream. Recovery and restore/import invalidate copied lease authority and queued writes rather than producing new physical input. Raw Human interaction may include control bytes, but arbitrary terminal escape output is observation data only.

Use Core's receipt authority and execution-control ledger, not a Swift/manual parallel work book. Any new durable control table must receive a separate agreed schema version rather than modifying the frozen12 receipt DDL or later reusing a frozen13 followup migration. M5 facts and existing WorkBook remain independent authorities in their proper domains.

## Whole-module acceptance

Exercise an actual owned helper/native/PTTY chain through public authenticated IPC and paired permissions with fake providers: exclusive claim, current generation, durable revocation before bytes, duplicate/mismatched request IDs, confirmed exact bytes accepted by PTY (not native application consumption), actual partial/interrupted writes, injected unknown writes, real resize, controlling PTY identity, reconnect/cursor gaps, observation bounds, slow clients, remote revoke, Stop/descendant cleanup, restart/restore/import no replay and mixed supported/unsupported runtime capabilities. Independent quality validates the complete user flow. Real native SDK/history/approval/model acceptance remains separately unknown and cannot be inferred from fake controls, plain PTY output or a source build.
