# ACP 第三条腿：给人拍板的一页（Todo #121）

<!-- doc-ref-base: 5a28e77 -->

两份长文（研判 359 行、方案 212 行）**只在工作区、没进 git**，结论有丢的风险，
所以这一页把「要人定的那一件」摘出来，并留下我作为机长的评审意见。

## 要你定的只有一件

**先接 `codex-acp` 当第三条后端，做到能起 session、能挂上 crew 工具、能跨进程恢复 —— 做还是不做？**

- **做**：多一条后端腿，而且**现有两家也都能改走 ACP**（claude 官方适配器由
  Anthropic + Zed + JetBrains 共同署名，本机实测跑通）。代价是多一层 node 进程。
- **不做**：维持现状两家，#121 那句「这套前端可以直接连接其它后端」暂时只是设计上成立。

## 我的意见：做，但**只做这一步**，并且**明令不许动 claude 那条 PTY 腿**

三条理由：

1. **它比预想的近**：ACP 覆盖了我们 `SessionBackend` 十三项必答里的十一项，两条完整
   回路本机都实测跑通了（`codex-acp` 和 `claude-agent-acp`）。
2. **第一家选 codex 是对的**：它有参照尺（同一句 prompt 有已知正确的后端可比）。
   方案里把 opencode 排第二，理由是「它没有参照尺」——这个排序我认。
3. **真正的产品取舍不在这一步**：ACP 给的是结构化事件流不是字节流，所以 claude 那条腿
   一旦改走 ACP，**可选中复制 / 回滚缓冲 / 改宽度重排就没了**。那是要你单独拍的一件事，
   **不该被夹带在「接第三条腿」里**。所以这一步明确划线：claude 留在 PTY 上。

## 已经知道的两个坑（方案里写清了，我复核过口径）

- **世界观注入 ACP 里没有统一入口**：claude 适配器有私有口子、codex 没有。落到
  codex-over-ACP 上，世界观只能拼进第一条 prompt 正文 —— 会进对话历史、会被压缩。
  **这是 ACP 的缺，不是我们的**，换任何一家都要重新长一次。
- **`mcpServers[].env` 不继承父进程环境**：crew helper 要的一切必须走 argv 或显式
  `env`。方案作者是被自己的探针骗过一次才发现的（标记写去了默认路径，探针盯着一个
  永远不会出现的文件）。

## 顺带一条与 #121 无关但值得知道的

普查六家的时候，**copilot 挂不上 crew 工具**，因此判出局 ——「一个不能 `post_to_crew`
的 session 不是 crew 成员」。这条读数是用修好之后的尺子重跑的：第一版探针对所有反向
请求一律回错误，于是**每一家都被读成挂不上**。
