# #112「把简明的习惯固化到产品里」其实卡在人类 Todo #16 上

<!-- doc-ref-base: 8d259b8 -->

今天对账时我把 **#112 归进了「排队」**。查下去才发现**归错了，它是 blocked_on_human**，
理由如下。

## 现状：机制齐了，缺的只有「严格到哪一档」

- 长消息**默认收起**（`CrewMessageFold.lineThreshold = 8`）。
- 收起态那一行来自 `headline`；作者没给就**猜**（前 3 段里第一个粗体/标题）。
- 作者没给时，回执里会把**猜出来的那一行原样摆给他看**
  （`CrewMessageFold.receiptHintIfGuessed`）。

那条 hint 的 doc comment 写得很清楚，是一个**刻意的设计选择**：

> schema 里的说明只在写之前被读到一次，而且多半没读。真正教得会人的是**出错那一刻
> 的那句话**。

## 我本来要做的、以及为什么没做

我原本打算把它从「提醒」升级成「拒收」：消息够长会被折、又没给 `headline` ⇒ 整条拒，
回执教他怎么写。

**没做，因为那是在替人类拍一个他已经被问过、还没答的问题。**
子机长在同一批活里明说过：「#142/#143 的**严格性档位**仍等人类 Todo #16」。
「提醒 vs 拒收」正是那个档位本身 —— #112 要的「固化」到底是软的还是硬的，
只有人能定。我单方面改成拒收，等于用一次实现替他答了那道题。

## 所以 #112 的正确分类

**blocked_on_human（卡在人类 Todo #16）**，不是排队。下次对账按这个归。
人答了 #16 之后，#112 的实现只是把同一个档位套到 `headline` 上，是小活。
