# Native APNs authoritative work notifications — complete module contract

Status: proposed typed contract before API freeze. Independent branch `codex/native-apns-20261023`, base49cac951. It does not alter Bbb033/20c, the fixed B Rust tree, current UI candidates, or the future single Linux build. No real Apple key, device token, APNs request, public listener, Worker, bridge or deployment is part of this source/local validation.

## Authority and event meaning

The current production source is **organization_work_events**, written by `store::work_organization::save` in the same transaction as the one organization WorkBook. Historical `work_events::append` is not the active producer. Add outbox insertion at that exact current save seam, after issuing original event identity/crew attribution and before commit. Failed work transactions leave neither event nor notification. No hub/operation Completed/session waiting/model text event is a substitute.

Stable identity: original remote transport authorityId + actual Core dbId + original source crewId + original immutable eventSeq. eventSeq is a canonical positive decimal string for the original u64 (current SQLite-backed producer further bounds it to i64). Installation identity is a per-device random UUID under that authority/database; local recordUUID, runtimeBinding, grant revision and display names do not enter the event identity. Each registration is owned by exactly one existing authentic mTLS grant and SPKI; it cannot move to another grant by guessing its installationId. Device re-pairing is an explicit new installation, not authority inherited from iCloud.

Event kinds: Done -> `done` (business work Done only); Reported -> `reported` (progress, never success); Blocked -> `blocked`; AskOpened -> `askOpened` (requires Human). Dropped is not a failure or successful Done and is not emitted by this contract. Provider/runtime failure remains outside these four business kinds unless a later authoritative kind is adjudicated. Defaults may select done/blocked/askOpened; reported is opt-in. One original event produces one delivery identity per installation, even after token/key rotation. No past-history catch-up on first subscription; only events committed after explicit registration are enqueued.

Preserve typed IDs: workId uses original WorkId string `W<n>`; askId uses original AskId `H<n>`; entryNo, where applicable, uses original EntryNo string `#<n>`, not UUID or unprefixed integer. Also retain the already-issued public object reference (`objectId`) for normal work.get/ask lookup; never assume a core W1 and public W1 are the same registry object. Any sources/entry numbers come from the committed event/state, not client text.

## Registration and public typed methods (CamelCase wire)

All methods use API3's normal bounded RPC, not a new HTTP server. Public configuration remains unavailable unless explicitly enabled by a Local Human under the existing managed lineage floor. Remote installation mutations are accepted only on the original live mTLS Principal, rechecked inside the same DB transaction; Agents and unauthenticated/sameUID callers are denied. OwnerWorkspace grants retain their existing Human crew access, with current crew existence/archive checks at subscription and before sending. This introduces no extra read/execute privilege.

- `notification.status` -> `{available, enabled, reason?, revision, environment?, topic?}`. No key/team/keyId/token returned. Disabled/unconfigured is explicit unavailable.
- `notification.configure` Local Human only, `{requestId, expectedRevision, enabled, provider?}`. provider is `{teamId,keyId,environment,topic,privateKeyPkcs8Base64}`; secret field is write-only, never Debug/logged/echoed. Reuse protected KeyStore unique slots (macOS Keychain; Unix current-owner regular non-symlink0600 under0700), storing only base64 DER as an ApiKey-compatible opaque string. Provider changes create a new binding/client and close old pools; no silent reuse across teams/topics/environments. Enabled=false needs no provider. Explicit configure is necessary after a restored trust epoch; no automatic push restart from stale grants.
- `notification.installationRegister` remote only, `{requestId,installationId,expectedGeneration,deviceToken,environment,topic,crewIds,kinds}`. expectedGeneration=`0` only for a first UUID, otherwise exact current positive generation. Device token is bounded hex bytes (not assumed permanently32 bytes); environment is `sandbox|production`; topic must equal configured topic. crewIds unique1..64, kinds unique1..4. New/rotate increments generation once and preserves the original event-dedup ledger. Tokens are not returned. Registering a revoked installation is rejected; use an explicit new UUID/grant, never resurrect a tombstone.
- `notification.installationRevoke` remote owner only, `{requestId,installationId,expectedGeneration}` -> durable revoked tombstone/current generation, clears sealed token, suppresses queued-not-started deliveries. Original grant revocation also immediately excludes new claims; no notification authorization survives its grant. An already-started attempt can still have reached Apple and cannot be withdrawn by this API.
- `notification.installationGet` remote owner only, `{installationId}` -> `{installationId,generation,revoked,environment,topic,crewIds,kinds}` or notFound, no token/key material.
- `notification.requestLookup` `{requestId}` -> `{kind:"notFound"}` or `{kind:"known",operation,result}`. Same authentic original owner/grant for installation results; only Local Human for configure result. Original UUID/digest binds each operation; response loss queries this method, never submits a new UUID/token or automatically repeats a mutation. A fresh installationGet is not a submission receipt.
- `notification.deliveryList` remote owner only, `{installationId,afterEventSeq?,limit}` (1..100) -> `{items,nextAfterEventSeq?}`. Each item `{eventSeq,crewId,kind,state,apnsId,reason?}`; state is `pending|unknown|acceptedByApns|rejected|suppressed`. At most fixed safe APNs reason codes are exposed; no raw response/error/URL/header/token/body.

Exact Rust DTO declarations and checked schema will be frozen once root accepts the necessary storage boundary below. Swift consumes these typed methods; no raw RPC or local fake registry.

## Durable state, concurrency, and recovery

Proposed **Store19** adds installation/subscription/request-witness/outbox tables and one existing protected version migration from18. Necessary writer barrier: an old18 writer executes the current `work_organization::save` without this new in-transaction producer, so allowing it to mutate an enabled notification authority can commit business events without required outbox records. A background scanner would not satisfy the same-transaction guarantee. Refuse old writers rather than invent retroactive events or a second authority. Current15/17 upgrade follows the existing guarded path through18 then19, Native16 remains rejected/inactive. No old product import, full historical migration suite, or new migration framework. Only fresh19/current18->19 and accurate old18 refusal plus original backup/rollback seam are in scope.

New installation token material is sealed with ring AES256GCM using a separate protected KeyStore seal-key slot; DB stores ciphertext only, with AAD binding authority/db/installation/grant/environment/topic/generation. Never generate/replace a missing seal key for existing registrations. Provider credentials use the same established secret protection policy; no new KMS/account service. Secret failure is unavailable, not a reason to drop work events.

Pending rows are inserted with the original work transaction for matching live registrations. Only one owned sender task selects bounded batches; there is no new general scheduler. Before external I/O, the DB actor transaction rechecks current identity/provider binding, installation generation/subscription, original live grant and current crew state, then atomically changes pending->unknown with one durable apnsId. This commits before the HTTP request is created/polled. Crash at/after that point never resends; timeouts, lost replies, GOAWAY/HTTP2 loss and unknown response keep Unknown. Explicit rejected responses remain rejected, not automatic retries (including429/5xx). Unknown cannot be laundered through key/token rotation, restart or a new request UUID. Fresh later work events remain independent.

Claim is the authority linearization point for an in-flight notification. Revocation suppresses all still-pending rows and denies later claims; an already-claimed Unknown is recorded as potentially externally sent and never reported withdrawn. Sender rechecks before starting I/O and skips a now-revoked claim; no guarantee can undo a request already accepted by Apple. Registration/config/revoke and sender claims use the existing FIFO DB actor and same transactions; await boundaries cannot overwrite a newer generation or revocation with a late response. Late response updates only the matching original apnsId/attempt, and cannot reactivate any registration. Invalid token responses disable only that exact generation; a late old-token failure cannot revoke a newer token.

Original Core restore already invalidates remote trust in its private staging transaction. Extend that same hook to disable registrations/provider binding and suppress pending work, retain historical receipts/Unknown. Thus restoring an earlier pending snapshot cannot replay post-snapshot external effects under newly-created grants. No remote trust or execution resumes automatically. Missing/mismatched authority/database/secret/restore binding refuses send.

## Native protocol and safe payload

Use existing reqwest0.13.5/rustls client with its official http2 feature, fixed APNs hosts only, TLS>=1.2 and negotiated HTTP2 enforced (no HTTP1 downgrade), ES256 ring P256 fixed64-byte signatures. Existing Jev feature unification gains HTTP2 code availability but its client settings/semantics stay unchanged; APNs owns a separate no-proxy, no-redirect, no-retry client, bounded connect/total deadlines and bounded response. No credentials inherited by Jev. HTTP2 local acceptance must verify actual TLS ALPN `h2`, authority/path/method/headers/body, response/error handling and one attempt; enabling a feature is not runtime qualification. New h2/necessary transitive registry versions/checksums are recorded; no unrelated lock updates.

JWT caches by exact provider binding: refresh at30min, never regenerate per event/retry or reuse across team/topic/environment; clock reversal/expired material makes sender unavailable. No automatic auth-error retry. APNs headers: alert push type, topic, original durable canonical UUID apns-id, the original durable enqueue time +24h expiration, fixed priority, content-type application/json, sensitive Authorization header; path token is never logged. No system proxy, redirect, server-chosen callback or client-chosen endpoint. Limit8s total/3sconnect and bounded error body.200 means `acceptedByApns`, never device display/read/task completion.400/410 invalid-token reasons revoke only the attempted generation; known non200 is rejected; malformed/oversized/mismatched apns-id/transport is Unknown. APNs does not offer a general receipt lookup that can prove an unknown send never occurred.

Fixed notification: localized generic PendingCrew work update, no title/body/prompt/task text. Custom context `{action:"open_context",authorityId,dbId,crewId,eventSeq,kind,workId?,askId?,entryNo?,objectId}` under4KiB. Clicking may only find an existing verified connection to that authority/database, check current grant and crew/object ACL, fetch present state, and navigate read-only. No auto pairing/connect/task/claim/restore/session start/resume; stale/missing/revoked context remains a neutral unavailable navigation. Push contents never grant authority.

Only affected schema/store/HTTP client tests run; no stable whole suite or new fixture platform. Real APNs credentials, Apple portal/key creation, device delivery/display/tap, signed entitlements and actual iOS/Mac registrations remain unverified and separately authorized.

## Complete daily trigger coverage before DTO freeze

The API envelope must use a tagged source identity, not force all sources into Work.eventSeq. A delivery has its own monotonic decimal deliveryId for pagination. Work contexts retain original eventSeq; session contexts retain exact original provider/Core identities in separate typed fields. There is no invented task revision. All sources share installation/grant/crew checks and the same Unknown-before-I/O outbox. Expiration is fixed at original commit/enqueue time +86400s, stored once, never refreshed by claim/restart/rotation; already-expired pending rows become suppressed. Apple receives that exact nonzero timestamp.
