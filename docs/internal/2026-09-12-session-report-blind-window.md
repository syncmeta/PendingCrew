## 顺带做的：三本账都不再吞东西

故障形状是 **`open()` 一个已存在的 inode 被拒，建新文件照样成**。所以「存不下来」
从来不是事实，只是没人去存。白板 / Todo / 驾驶舱现在都会把写不进去的内容存成新文件，
账恢复可读时按原顺序补回，并在回执里说清楚。机制抽成一份 `LedgerSpool`（`MultiProcessJSONStore.swift`）。

## 故障本身：这一窗排完了能看见的层

| 候选 | 读数 | 判定 |
|---|---|---|
| TCC | 20 分钟 616 行里文件类服务 **0** 次 | 排除 |
| 内核沙盒 | 别的进程 70 行真 deny，我们 0 行 | 排除（尺子会响） |
| provenance | 三个目录同秒建文件，值**逐字节相同**，坏文件上也读得出 | 排除 |
| 第三方 ES 客户端 | 632 个进程里 **0** 个（苹果自己 2 个） | 排除 |

**被拒的只有 `open()` 一个系统调用**，`stat` / 列目录 / `unlink` / `rename` /
`listxattr` / `getxattr` / 建新文件全通。下一步只剩发作当口
`sudo scripts/capture-eperm-fsusage.sh`（它看不到「谁拒的」，这条边界写在脚本里）。
