# PendingCrew：本轮工程形成的成本与质量设计约束

这些经验来自统一工作账本、Codex恢复及客户端接线过程。它们进入产品设计；不是实际账单节省比例，尚未测量每项节省的token数量。Jev和记忆后端仍先讨论定案。

| 经验 | 产品约束 | 当前证据及边界 |
|---|---|---|
| 工具回执重复全文会无端扩大后续上下文 | 写操作回执返回编号、当前版本和精简摘要；详情按需读取。长目标、验收、证据和待交接正文不重复回灌 | work_item_block回执已改WorkSummary并清除pending长note；独立socket长正文marker验收通过，work.get仍返回完整内容 |
| 状态、编号或作用域歧义会导致重复追问和错误操作 | 公共全局ID与旧别名明确分开；错误保留code/data/当前事实；跨机组拆分默认继承目标机组 | 公共H不再猜本地H；foreign-home-owner分拆与CAS/越权无副作用独验通过；Swift错误保留实际NDJSON字段 |
| 每个机组重复读取完整组织账会随机组数量放大成本 | 定时扫描按组织批处理一次，再按对象机组应用冻结/权限规则；共享语义函数，不为每项重扫整图 | checkpoint组织扫描与默认批处理已接；两机组默认答复/失败回滚测试通过。性能收益尚未做数量基准 |
| 一个负责人多项变化不应引发多个无益唤醒 | 同一事务收集真实受影响项，按当前负责人合并耐久通知；未解除最后阻塞时不唤醒 | 实际socket/actor验证多个W合并一条通知，保留其他H阻塞；送达需要真实执行器回执 |
| 重连、过期提醒和未知投递结果会制造额外模型轮次 | 读状态恢复与写命令分离；写操作不自动重放；render后在claim重检owner/revision/终态 | 故障恢复与实际actor过期claim回归已有证据；Swift迟到读/重连/CAS失败不会重发命令 |
| 为证明接口正确而反复运行真实模型成本高且覆盖弱 | 用实际RPC/MCP/actor seam加确定性fake执行器证明协议和竞态；真实账号只用于需要真实兼容性的交付关口 | 本轮新验收未唤醒真实模型；fake的通过不能冒充真实账号、GUI或日常数据验收 |
| 旧测试夹具错误会把时间与注意力消耗在假故障上 | 旧版本测试运行真实历史迁移链；保留原失败日志；不伪改新库版本号，不放宽产品规则迁就旧预期 | v4–v8历史夹具已验收；正式Store升级与备份拒绝有红绿证据；协作整合失败仍需分类修复 |
| 重复全审和全量输出会挤占有效工作上下文 | 独立代理按文件/验证层分工；消息传结论、源码版本、证据路径、下一门槛；只在影响变化后重跑相应门禁 | 统一账本分为core/store/socket/actor验收，最后必须组合gate。定向绿不能替代整体验收 |

## 需求入口与客户端整合新增经验

- 未知提交结果不是“失败后重新做一遍”。原始需求以窗口草稿持有的UUID进入后端幂等创建，未知结果保留原文与同一UUID；编辑后的新草稿不丢失旧不确定提交。确认必须显式操作，不能自动唤醒模型补问或自动造第二需求。真实daemon组合及UI草稿回归通过。
- 同一编号并不足以证明详情更新更晚。需求无revision时，列表与详情用本地读提交水位双向拒绝旧响应；回执必须证明精确原文/关闭状态/理由，而非收到任意同ID对象就清草稿。两轮独立受控RED到GREEN证明了真实可发生的读竞态；这里修本地一致性，避免让agent追逐矛盾状态，尚未量化token收益。
- 扩展协议时先同步可执行方法覆盖和工具目录契约。生成schema/工具快照不替代实际RPC调用；新增接口加入正常daemon逐方法验收，目录只读标记与角色变化也实测。完整门禁发现旧数量期望后定向补验，不用改产品权限迁就夹具。

## 尚需实现或测量

- 使用已有runner_usage原始快照建立可解释的使用视图，保持未知与零分开、累计快照不相加；不要凭调用次数估算账单。
- 后续知识/记忆检索遵守按需读取与有出处、可失效原则；不把所有历史每轮灌入提示词。具体实现仍待方案讨论。
- 新工具契约默认预算化摘要，细节通过稳定引用读取；权限失败、CAS冲突和断线不能触发无条件自重试。
- 正式运行后再测量真实任务级使用与重复唤醒，验证收益；保证权限、耐久性、故障可见及可恢复性，不能以省token为由删除质量门槛。

## 持续工程协调与交付新增经验（2026-10-14）

- 主协调者按完整可验收模块分配长期所有权，局部实现/失败修复由作者和质量线直接闭环。根只接范围、依赖、跨线政策、冻结及交付。一个小检查结束不能意味着工程停止；向已完成agent发普通消息不等于重启。本轮实际修正了这些组织问题。后续PendingCrew协调设计应由真实模块结果、待决冲突或运行终止事件触发接续，状态不变不重复唤醒模型；该自动协调产品机制尚未完成，不能以本聊分工代替实现。
- 后台编译与GUI打包可解耦，但复用必须有完整可核输入、实际编译记录和原产物，而不是声明同一个Git SHA。小合成结构验收可以验证证据校验器的拒绝能力，实际编译仍需独立留证。跨commit可复用字节相同的Rust输入，减少重复冷构建；尚未测量token或时间收益。
- 源码相同也不能忽略toolchain、target、profile及feature条件。复用证据需记录实际构建配置并与最终候选选择核对；debug独立候选可以明确选择，不能冒称默认feature release，更不能隐藏testkit差异。这个配置核验已交客户端/质量线补齐，当前小结构验收不证明它已经实现。
- 不为已有权威账的每个视图再造一套生命周期。群Todo用实际channel引用投影，四视图分类用独立引用树，工作状态仍由唯一book产生。这同时减少重复上下文、状态同步代码与矛盾修复；实际完整产品验收仍在途，不凭架构判断宣称已有节省比例。
