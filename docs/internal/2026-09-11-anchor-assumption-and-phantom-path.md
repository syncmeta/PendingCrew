# 两条比病根更有复用价值的东西（#144 / #143 顺出来的）

写这份不是为了记录那两个 bug —— 它们各自的病根写在
`8d683ed` 和 `docs/internal/2026-09-11-structured-message-fields-plan.md` 里。
这里记的是**下一次遇到别的东西时还用得上的那两句**。

---

## 一、一个正确的设计，被用在它假设之外的第二种变化上

`ChatScrollAnchor`（`Sources/Mac/Views/CrewChatView.swift:1747-1759`）在**不跟随**时
把尺寸变化锚在**内容顶端**：

```swift
.defaultScrollAnchor(isFollowing ? .bottom : .top, for: .sizeChanges)
```

这是对的，而且理由很清楚：用户滑上去看历史时，新消息在**下面**长出来，
锚住顶端 → 视口纹丝不动（Todo #47 行为 3）。

**但「尺寸变化」有两种，它只假设了一种。**

| 变化 | 发生在 | 锚顶端的效果 |
|---|---|---|
| 新消息追加 | 内容**下方**长 | ✅ 视口不动 —— 设计要的 |
| 渲染窗口把最老一条剪掉 | 内容**上方**缩 | ❌ 视口里的内容整体上移 |

同一个锚点，对这两件事的效果**正好相反**。#144 就是第二种：
`CrewChatWindow.afterInsert` 在用户没翻过页时不补上限，于是新消息一到、
窗口仍取「最近 12 条」，最老那条被剪掉。

**所以 #144 不是「守卫写错了」。** 守卫和锚点各自都对，错在
**没人问过「这个锚点对第二种尺寸变化也成立吗」**。

> **可执行**：给一个已有的锚点 / 补偿 / 守卫加**新的触发来源**时，
> 先问「它当初假设变化发生在哪一侧？我这个新来源在同一侧吗？」
> 同一侧才直接复用，不同侧就是一个新情况，得单独判。

这条不止管滚动。任何形如「发生 X 时做 Y 来抵消」的补偿机制都有一个隐含的方向假设，
而**第二个触发源进来时，那个假设不会自己报错**。

## 二、注释描述的不是「过时的事实」，是「一件从没发生过的事」

`CrewMessageFold.fold(_:threshold:explicitSummary:)`
（`Sources/Models/CrewMessageFold.swift:52-63`）有这样三样东西：

1. 一个形参 `explicitSummary: String? = nil`
2. 一句文档注释：「发送者显式给的摘要（`post_to_crew` 的 `summary`）。给了就用它，**最可靠的一级**」
3. 一个 `guard`：`explicitSummary?.…nilIfEmpty ?? derivedSummary(text)`

三样凑在一起，读起来像「这个功能做好了，而且有优先级设计」。

**实际上那条路整条不存在**：`post_to_crew` 的 schema 里没有 `summary` 参数、
白板落盘没有 `summary` 字段、全仓 0 个调用点传它（唯一 call site
`CrewFoldableMessageText.swift:26` 传的是 `fold(text)`）。
**从上线到 2026-09-11，那一级一次都没跑过。** 每一条折叠消息的标题都是猜的 ——
人类抱怨的正是这个。

这是「静态文本描述会变的事实」的一个**更坏的变种**：

- 常见那种：注释曾经是真的，后来代码变了，注释过期 → 还能靠「查 git 历史」发现。
- 这一种：注释**从来没真过**，它描述的是一个当时打算做、最后没接上的计划。
  它没有「过期」的时刻可查，`git log` 上也看不出异常 —— 它诞生的那天就是假的。

而它**比过期注释更能骗人**，因为形参和 `guard` 会替它作证：
读的人看见「参数在、分支在、注释在」，三个独立证据互相印证，
**而它们其实是同一个人在同一分钟里一起写下的**。

> **可执行**：看到「某个更可靠的路径 / 更优先的分支」这类描述，
> 先 grep 一下**谁在传它**。零调用点 = 这条路没有被走过，
> 不管形参和分支写得多完整。
> 同族判据：一个从没被触发过的检查、一个从没红过的测试、一个从没被传过的参数 ——
> **都要先证明它会发生，再信它的描述。**

（另一半在 `feedback_a_check_that_never_fires` 那条：「没发生」和「触发不了」长得一样。
这里是第三种：**「从没被接上」也长得一模一样**。）
