# docs/internal —— 开发过程记录

这里面的东西**不是用户文档，也不是当前状态的说明书**。它们是某一次具体改造
动工前后写下的施工计划、清点表和实测记录，带日期前缀、写完就冻结，**不会随
代码更新**。读的时候请按「2026 年 8 月某天，那个人是这么想的」来读。

留着它们，是因为这类文档记的是**「为什么当时这么改」**——那部分信息代码里
看不到，也没法从 git log 反推。想动某块地基之前翻一翻，能省掉一轮重新踩坑。

想知道**现在**是什么样，看这几处，别看这里：

- 根目录 `README.md` —— 项目是什么、怎么构建、怎么跑
- `CONTRIBUTING.md` —— 怎么参与、改动要过哪些关
- `docs/release-macos.md` —— 怎么出一个能装、能自动更新的包
- `docs/tech-debt.md` —— 已知的债，还在滚动更新的一本活账
