# Apple personal data module (separate from A)

One actor/writer owns each account+collection file. Supply a stable random per-install device ID; never derive it from the current credential or clone it to another device. `AppleDraftKey` uses actual original data.workspace.get DataContext authorityId + dbId + crew + channel/original session + draft kind. Validate dbId against the currently verified Core identity. Core currently sets this authorityId to its actual dbId, consistently across local/remote access. Transport authority/SPKI belong only to pairing/directory, never this content key. Grant, runtime binding, record UUID and generation are excluded.

`AppleBranchStore<Payload>` accepts only a caller-chosen Codable draft/directory payload type. For chat use the original `CrewComposerDraftStore.Draft` (text/stagedMentions/replyTarget). Never pass journal prepared commands, StoredPair, approval state or credentials. Payload bytes are preserved through sync. Sync/open/reconnect have no Core client dependency and cannot send/claim/start/resume.

Checkpoint updates only this device's active branch. Other device branches remain visible. Explicit resolve creates a new branch and retires specified branch IDs atomically; retire is permanent, wins over all later stale updates, and must be confirmed by UI. Do not GC tombstones without a separate protocol. Checkpointing coalesces own branch, not permanent keystroke history. UI may debounce and must show local write/sync status; errors retain the latest in-memory payload and last durable file.

Account identity is explicit container+environment+actual CloudKit userRecordID. Local-only data uses a separate nil-account scope. Selecting a cloud account never migrates nil/old-account branches. Account change invalidates in-flight work and reloads the selected partition. Import/copy between accounts requires an explicit user action outside this module.

Cloud directory payload is a typed allowlist: display host, portable tls://host:port endpoint with an explicit valid port (public IP or explicit LAN/DNS hint), verified transport authority/db/SPKI. It is discovery only. UI never auto-connects; new devices independently enroll and remain revocable. KVS stores only two small presentation preferences, no drafts or host blob.

CloudKit is an explicitly invoked private-database adapter with an explicit configured container/environment; application entitlement must match environment. No default identifier, no entitlement edits, no actual account access as part of fixtures. API uses CAS and stops on conflict/failure. Subsequent user-requested sync re-fetches, merges, and retries normally. Account notifications cancel tracked operations; caller must also promptly clear account selection on notification before accepting UI edits for another account.

Real qualification remains blocked on approved container/entitlement, signed Mac+iOS builds, two-device account-switch and concurrent/offline tests. Simulated transport results are not iCloud acceptance.

UI integration defaults: until an approved signed container/entitlement and explicit user cloud opt-in exist, do not construct/use `AppleCloudKitTransport` or `AppleLightPreferences` with a real ubiquitous store. Use account:nil; show “草稿仅本机保存”. The existence of source code is not a qualification signal. `accountIdentity()` is an explicit real account operation and must not run during candidate startup. `synced` only means a completed adapter exchange for the current account revision; only real CloudKit qualification permits labeling it “已跨端同步”. A MemoryCloud test result must never be reflected as that production status.

Normal local reopening: instantiate the same account+collection+install device ID, then read active branches. Auto-restore only the device's own branch into an empty input; never overwrite a nonempty composer. Surface other device branches as choices. Merging/selecting calls resolve with an explicit list of branch IDs to retire. To start a merged local branch, retire the current local branch too; omission is rejected, not silently overwritten. `resolve(payload:nil,retiring:...)` explicitly deletes selected branches. Local recovery originals behind remote tombstones remain separate from active/cloud data; offer explicit view/export/restore, never auto-resurrect.

Tombstones are retained indefinitely, contain no body, and count against the same hard file limit; reaching the limit visibly fails local save and keeps current text in memory. No automatic tombstone eviction or historical audit database exists. User-approved cleanup/compaction needs a future device acknowledgement protocol and is outside this module.

CloudKit wire shape: private default zone, PCWPersonalBranch record type, collectionID String (queryable index required), payload Bytes. Record name hashes explicit account/collection and branch UUID. Each branch record contains only latest checkpoint or body-free retirement. Direct fetch of all local IDs supplements query results so an index cannot hide a known tombstone. CAS ifServerRecordUnchanged, per-record failures surfaced; no automatic conflict retry. Query/fetch results are bounded and account identity is checked before save batches and after completion. Account notifications invalidate/cancel tracked operations immediately. Signed CloudKit entitlement chooses actual environment; the explicit environment value must be matched during signed qualification, not inferred from runtime labels.

Apple primary references checked 2026-10-22: https://developer.apple.com/documentation/cloudkit/cksyncengine-5sie5 ; https://developer.apple.com/documentation/cloudkit/ckmodifyrecordsoperation/recordsavepolicy/ifserverrecordunchanged ; https://developer.apple.com/documentation/cloudkit/ckcontainer/fetchuserrecordid(completionhandler:) . Bundled Xcode SDK CKContainer.h and CKModifyRecordsOperation.h confirm account notifications, temporarily unavailable preservation and change-tag CAS. The module uses bounded explicit operations rather than a second CKSyncEngine persistence framework.
