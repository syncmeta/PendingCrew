## 1. 为什么要单独立一期

人类给这条线的口径是四件事：**后台持续、同机自动连接、异机一次配对后加密直连并可重连恢复、
无账号 / 无云中继依赖**。

原设计（2026-08-19）**只覆盖前两件**。它对第三件的原话是 §1.3：

> **不做手机远程遥控** —— 但它是这套常驻 runner 的已知下游消费者，协议设计要为它留门（§4.1 传输层可替换）。

所以异机不是「P5 漏了」，是**从来不在 P0–P5 的范围里**。它需要自己的一期。

## 2. 好消息：接缝真的留出来了（这一节是读代码读到的，不是推的）

`SessionMessageLink`（`Sources/Mac/LocalRunner/UnixSocketTransport.swift:15`）就是那道门。
它只要求六件事：`onReceive` / `onClose` / `isOpen` / `isSynchronous` / `pendingWriteBytes` /
`send` + `close`。**协议、编解码、attach/快照、重连策略、viewer 全部长在它上面，不认识底下是什么。**

今天已经有四个实现，其中两个是生产代码：

| 实现 | 位置 | 是什么 |
|---|---|---|
| `InProcessSessionLink` | `Sources/Mac/LocalRunner/UnixSocketTransport.swift:85` | 同进程直调（P2 那条路） |
| `UnixSocketTransport` | `Sources/Mac/LocalRunner/UnixSocketTransport.swift:139` | 本机 UDS（P4 那条路） |
| `ByteStreamLink` | `Tests/.../SessionProtocolOverSocketTests.swift:228` | 测试替身：**按任意字节边界切分/粘包** |
| `BackpressureLink` | 同上 `:244` | 测试替身：写不动的链路 |

第三个尤其值钱：`test_server接受任意切分与粘包的可靠字节流` /
`test_client接受任意切分与粘包的可靠字节流` 已经证明**上层不依赖投递边界等于帧边界** ——
而那正是 WAN + TLS 上必然被打破的假设（`docs/tech-debt.md` 里那条 🔴 说的就是它，P4 已接上
增量解码，见下）。**所以异机传输是加第四个实现，不是重做。**

`isSynchronous` 也已经被诚实地建模：socket 上返回 false，`RemoteSessionBackend.screenText`
据此降级说「读不到」，而不是编一段空白当画面。异机链路照抄这条即可。

## 3. 范围（做什么）

1. **一个新的 `SessionMessageLink` 实现**：TCP（或 QUIC）+ 认证加密。
2. **一次配对**：两台机器互换长期公钥并各自钉住对方，之后**不再需要任何第三方**。
   配对通道由人完成一次（二维码 / 一次性短码 / 手动粘贴皆可，本页不定）。
3. **重连恢复**：复用现成的 §4.5 —— 断线退避重连 → `hello` + `listSessions` +
   对当前在看的那个重新 `attach` 拿**新快照**（不是接着旧字节流）。这条在同机上已经跑通，
   异机不另写一套。
4. **发现**：同一 LAN 下能自动找到对端（Bonjour 之类）；不在同一 LAN 时由人给地址。

## 4. 明确不做（写死，免得下一个人以为漏了）

- **不做账号、不做云中继、不做中转服务器。** 这是人类的硬口径，也是这条线选「配对 + 直连」
  而不是「登录 + 中继」的全部理由。
- 不做 NAT 打洞的兜底中继（打不通就打不通，告诉人为什么）。
- 不做多台前端同时编排 —— 编排者永远只有一个（§6 的防双头对异机同样成立，
  而且异机让「第二个编排者」更容易出现，闸门那套判定必须原样适用）。
- 不做手机端 UI。手机是**已知的下游消费者**，但那是另一条线的事。

## 5. 完成判据（先写下来，免得到时候拿「连上了」当通过）

1. 两台真机：A 机跑 daemon，B 机跑前端；**一次配对之后**，B 关掉再开能自动连回 A 并
   恢复同一个 session 的画面与对话。
2. **拔网线级别的断线**（不是优雅关闭）之后能自己接回来，且 A 上的 session 全程没断。
3. 中间人换掉公钥时**连不上并明说原因**，不静默降级成明文或「换个密钥继续」。
4. 全程**不经过任何第三方服务**：抓包证明只有 A↔B 两个端点。
5. **不许出现双头**：B 机上的前端拿不到编排权（`OrchestrationGate` 的判定对异机照样成立），
   A 机的 daemon 仍是唯一编排者。
6. 同机那条路（UDS）**行为一字不变** —— 异机是加一个实现，不是改现有那条。

## 6. 前置

- P5a 完成（默认切 daemon 之前，异机没有意义：前端连的是一个不存在的常驻后台）。
- P5b 的半开连接回收（`SessionReconnectPolicy.daemonIdleTimeout`，当前**声明了但全仓
  没有第二处引用**）在异机上从「整洁问题」升级成「必须」：WAN 上半开连接是常态，
  不回收就会堆到把 daemon 拖垮。
