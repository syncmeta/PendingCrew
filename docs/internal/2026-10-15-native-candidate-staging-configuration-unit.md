The NativeCandidate stamp requires an explicit 40-character lower-case hexadecimal PENDINGCREW_CANDIDATE_SOURCE_REF. Missing/bad ref or missing product Info fails before any stamp writes. This is a build-input correlation, not authority authentication. Final immutable packaging must verify the full actual source input set and config against that ref; merely setting a ref does not prove provenance.

The candidate factory now uses the platform application-support directory plus PendingCrewNativeCandidates/ref on Mac and iOS. A candidate missing/bad bundle ref returns no directory even if an explicit data-dir was supplied. Ordinary PendingCrewCore remains stable. The new mobile recipe uses the existing committed source-inputs/SPM inventories and warm DD/SPM, checks its own frozen recipe bytes, verifies before/after full inputs, and builds the original target with NativeCandidate, the exact explicit ref, candidate bundleID, no Team/profile/entitlement and CODE_SIGNING_ALLOWED=NO. ## Ordinary runtime behavior affected by the same cut

Original AppModel now validates and prepares its private local presentation directory on iOS as well as Mac before choosing authority. Both original iPhone/iPad navigation paths use it. It marks the selected Workspace journal required before exposing any adapter. Failed or incomplete journal validation publishes no writable adapter and an explicit error while retaining the same socket for read-only diagnostics. It does not kill/Stop the daemon, clear unknown history, switch to legacy, or replay a request. Strict owned Quit retains its established ownership/limited-close contract.

Workspace journal preparation captures generation, actual client connectionEpoch, runtime and authority binding. It validates/rehydrates complete history before assigning the journal/scope/history. Late results cannot create or publish into the new scope; an old task cannot clear the newer preparation token. A failed current connection is not automatically retried by notification feedback; an explicit new connection can retry after the underlying condition is repaired. AppModel rechecks selected Workspace, generation and connectionEpoch after await before publishing. Error setters avoid feedback loops.

Readiness requires actual current connection, completed journal/scope, matching receipt database, and (for remote) the same authority/database/grant/revision. Both direct mutating RPC fallback and public command/terminal bindings refuse with typed notSubmitted when required readiness fails. These are actual guards; an error label alone is not the write prohibition. Existing current-authority read calls remain available. Same-DB/new-runtime histories preserve the original request/runtime envelope, while cross-DB/grant changes cannot obtain a writable binding. No public schema or wire changed.
