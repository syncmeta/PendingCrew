## Authority and content

Core execution/work/trust/receipt authority stays bundled SQLite; a separate qualified stdio worker is the only DoltLite-linked process, with no listener/principal/network credential access. One stable namespace per crew data workspace, independent of branch/path/Pod URL. Restore preserves namespace; explicit workspace fork receives a new namespace. Core owns current crew/namespace mapping, restoreEpoch and worker admission. IDs are server-assigned UUIDs and never reassigned, including after archive/version rollback; creation aliases are request-local references resolved before publication, never persistent IDs. Core request metadata retains created-ID tombstones across Dolt version restore. Historical filesystem rollback outside supported restore is explicitly not an exactly-once guarantee.

Blocks have semantic identity/type/JSON content/provenance/revision; they are not mechanical token slices. Views and content are separate. Document views are ordered stable placement IDs, allowing the same block multiple times and across views. Live placements use current captured branch content; pinned placements use an exact commit. Historical views resolve all unpinned blocks against that view snapshot, not today's HEAD. Shared edits affect live references; fork explicitly creates a new block and source provenance. Archive retains content/history and produces an archived reference state, not cascaded deletion. Relations are stable-ID typed many-to-many links; task/person/domain data is not a second WorkBook and never modifies work ownership/completion or reply/@/Ask.

User-defined business schema/tables/views/fields and SQL are first-class within the knowledge file, beside protected minimal system envelopes. Raw values use explicit NULL/integer decimal string/IEEE double/text/blobhex; absent JSON keys remain absent and unknown JSON attributes remain intact. User SQL cannot modify Core databases, UUID/control/permission/renderer grants, ATTACH/DETACH, pragmas/extensions/files/network or dolt control functions. Admission uses the actual pinned engine authorizer and prepared single statements, not text matching. Nested triggers/views and protected virtual-table routes must be covered in real-engine whole acceptance. Queries are read-only, scoped, deadline/byte/row bounded. No query/get/history/lookup silently initializes a workspace or writes state.

## Complete RPC set

- `data.workspace.get(DataWorkspaceGetParams) -> DataWorkspaceInfo` — state ready/uninitialized/unavailable. Namespace mapping comes from Core16 crew/authority metadata. Missing engine never falls back to legacy document tables.
- `data.submit(DataSubmitParams) -> DataChangeResult` — the only general mutation endpoint: initialize, atomic edit batch, branch create/switch/merge, version restore, explicit Unknown-barrier acknowledgement. Changes include free SQL as well as semantic block/view/relation edits.
- `data.request.get(DataRequestGetParams) -> DataRequestGetResult` — pure original UUID query, known/notFound/historical. Known may itself have Unknown phase; notFound is not proof of nonexecution. This never replays submit or synthesizes a new UUID.
- `data.object.get(DataObjectGetParams) -> DataObjectDetail`; `data.object.list(DataObjectListParams) -> DataObjectPage` — typed content/provenance/current or pinned reads, with affected live-view summary capped and marked when incomplete. Foreign invisible references become unavailable placement placeholders; no private title/body/count is derived. Direct unauthorized workspace requests fail before object lookup.
- `data.schema.get(DataSchemaParams) -> DataSchemaResult` — user schema definitions/declared types/PK order/default SQL, excluding protected controller metadata.
- `data.query(DataQueryParams) -> DataRows` — one readonly SQL statement with bound typed values and cursor bound to namespace/query digest/exact snapshot. No implied sort: `stableOrder=false` for arbitrary SQL; caller SQL defines its order. The UI must not claim deterministic full coverage for unordered SQL. Limits/truncation are explicit, never an implicit complete result.
- `data.table.get(DataTableParams) -> DataTablePage` — deterministic keyset pagination when a usable declared PK exists; tables without a stable key return bounded rows and explicit unstable/truncated state, never a guessed complete cursor.
- `data.history(DataHistoryParams) -> DataHistory`; `data.diff(DataDiffParams) -> DataDiff`; `data.branches(DataBranchesParams) -> DataBranches` — real Dolt commit ancestry/row+schema changes/branches. All cursors bind snapshot and namespace; max100/page. Public `table=null` covers user data plus typed object projections; protected `_pc_meta/_pc_requests` are never exposed as raw tables/diffs.
- `data.export(DataExportParams) -> DataExportPage` — pure bounded typed logical export of one exact commit with visible refs/explicit unavailable placeholders, exact source/schema/cell distinctions and `complete/next`. It is not a Solid/Pod implementation or primary Git store. Full native file/history backup is a separate local authorized maintenance bundle, not exposed to view JavaScript or reduced remote grants.

Existing `document.create/get/list/update/delete` and trusted MCP spellings remain available, now adapting only to Core16 Dolt authority. Existing IDs/revisions/actors/folders/ObjectRefs and idempotent create semantics remain. Legacy textual create/import creates semantic paragraph/heading blocks with exact separators and a document view; ambiguous segmentation retains an explicit whole semantic block instead of token splitting. Reconstructed text is byte-exact. Old document.update is an explicit whole-document replacement CAS: it forks/replaces affected content rather than silently changing other documents' shared blocks. New block editing is the explicit shared-edit path. Deleted documents/views archive, preserving prior versions. Agent reads retain existing bounded document body chunks. Older helpers with no capabilities remain disabled by the client.

## Version publication and unknown outcomes

Every data.submit carries original UUID plus dbId, authorityId, restoreEpoch, crew, namespace, branch and expected HEAD. Core verifies authenticated Human/trusted MCP actor and current membership/frozen state; remote grants remain narrower, agent direct Human RPC cannot bypass MCP. All link targets and views are visibility-filtered against current authority, including after revocation. A stale authority/branch/HEAD/object revision fails closed. Context fields are constraints, never JSON proof of identity.

Core writes only control capsule/hash/phase/created IDs/result references into its durable request ledger before dispatch; no block bodies/code/SQL result content is duplicated into the execution DB. The actual content, views, schemas, provenance and versioned UUID effect fact live in DoltLite. Apply runs BEGIN IMMEDIATE, content+request facts, then final dolt_commit; official semantics and actual controls show that successful final commit ends and durably publishes the SQL transaction too. SQL COMMIT alone is not version success. After a lost reply, sameUUID submit is read-only and original lookup compares a unique real version/request witness. Unknown or damaged facts establish a per-namespace publication barrier; no automatic retry or fresh UUID. Version/ref operations have distinct official durability behavior, not a blanket rollback promise. Merge captures both target and source heads; conflict failure rolls back real uncommitted conflicts, returns bounded typed conflict facts, and a new explicit resolution operation can use ours/theirs per table. Schema conflicts require aligning schemas, not an automatic choice. No conflict is silently committed.

Branch/reset effects may complete without a unique committed UUID witness; if final response is lost they remain Unknown even if current state resembles the target. ResolveUnknown is an explicit authenticated Human acknowledgement of observed HEAD and original request, clears the barrier without replay or retroactively claiming original execution. A subsequent explicit restore is a separate UUID. Acknowledgement/restore cannot be generated by business SQL or JS without the host's granted knowledge-write path. Known/settled and historical requests never re-execute.

Link facts are solely in the Dolt transaction; Core work objects are checked but not mutated, and captured revisions are provenance rather than an ongoing work grant. There is no claim of atomic transactions across the two engines. Reads recheck visibility before returning; removed/closed targets surface stale/unavailable references without deleting historical link facts.

## Views and rendering

DataViewDefinition stores native document composition or an explicit renderer/version plus HTML/CSS/JavaScript/bindings/declared knowledge capabilities. Initial supported code renderer is `web`, version `1`; unknown versions are persisted but marked unsupported, never evaluated as a fallback. Code is opaque data to Rust/DoltLite. Native host validates the exact WK instance/main-frame, namespace/view version/generation and locked CSP; no fileURL, ambient network, credential, Core administration or generic RPC bridge. Read is default; knowledge write requires explicit native-host scoped grant and Core ACL/CAS/UUID checks. View code and free SQL cannot modify grants or request-journal control state. Cross-scope reuse does not transfer ACL. External synchronization/WebID/Pod/ETag mappings are independent future control-plane data, not fields injected into every business table.

## Limits and pagination

Mutation count<=64, SQL statement params<=1000; logical text/blob content<=1MiB per block/cell; encoded object cap8MiB, whole protocol/frame<=16MiB. Object/page limits default50/max100, SQL rows max1000 with explicit cursor/truncated; structured view placements max4096. Code bundle logical source total<=1MiB; arbitrary JSON attributes persist losslessly within the encoded cap. Canonical integer/revision strings preserve64bit values; f64 must be finite. Response byte budget is enforced and returns an explicit bounded/incomplete error rather than dropping fields/rows. References/page cursors bind namespace/authority epoch/exact commit. Truncation or unsupported media/renderer never reports complete. Content transport chunking is a wire budget mechanism, not a semantic token segmentation policy.

## Closure02: creation, lookup, historical references and lossless redaction

### A complete write-batch ID example

Creation aliases are ASCII `[A-Za-z0-9_-]`,1..64bytes, unique across the whole request (objects and placements). Before any Dolt mutation the trusted controller allocates all UUIDs durably in the Core intent capsule, resolves types, and rejects unknown/duplicate/incorrect-kind aliases. Forward references within one batch are supported. Literal DataRef never means an alias; `DataInputRef.created(alias)` does. Same UUID lookup returns the same created map; Unknown never reallocates/replays. Restore/version rollback cannot authorize reusing a retired ID.

Example edits (normal JSON enum tags, not ad hoc `@alias` strings):
1 createBlock `{kind:"createBlock",alias:"intro",contentType:"text/markdown",content:"One shared introduction",sources:[],attributes:{}}`.
2 createView alias `docA`, definition `{kind:"document",placements:[{kind:"set",id:null,alias:"pA",block:{kind:"created",alias:"intro"},atCommit:null,layout:{}},{kind:"set",id:null,alias:"pB",block:{kind:"created",alias:"intro"},atCommit:null,layout:{}}],layout:{}}`.
3 createRelation alias `relA` uses `{kind:"created",alias:"intro"}` as subject and an explicit authority-checked existing task DataRef as object.
Result created.intro is `{kind:"object",object:{reference:{namespace,kind:"block",id:UUID},revision:"1"}}`; created.docA is the view; created.pA and pB are distinct `{kind:"placement",id:UUID,parentView:{reference:viewRef,revision:"1"}}`. Order is the placements array; identity is never array position, text hash or branch path.

For a new placement Set requires exactly one new alias and no id; for replacing an existing visible placement Set requires its id and no alias, bound to that same parent view/expected revision. Keep `{kind:"keep",id,layout}` retains the protected original target and pin semantics, permits reordering/layout edits, and is valid only for that parent view's existing placement. This supports saving an owner view whose foreign reference is now inaccessible without guessing IDs or deleting hidden links. Keep cannot copy an inaccessible placement to another view. Code binding Keep similarly retains only the same parent view/binding ID; Set uses explicit input references. Update sources=null preserves the existing protected sources; a supplied vector is an explicit replacement of authority-checked sources.

### Pure lookup is not a stale-state CAS

`data.submit` is constrained by current authenticated actor plus current dbId/authorityId/restoreEpoch/crew/namespace/branch/head and per-object revisions. Its first durable intent precedes dispatch. A duplicate known UUID is returned read-only before any mutation; changed immutable payload is conflict. Same UUID Unknown never redispatches.

`data.request.get` uses the supplied context as the original request coordinate, NOT a current HEAD or branch CAS. It authenticates the actual current connection and checks current read authority to the original request crew before reading the Core capsule. Original head may differ and original branch may be deleted; neither blocks lookup. A foreign dbId is an authority mismatch, not a search of another database. Current authority/restoreEpoch mismatch within the same DB makes an extant record Historical, preserving its original recorded phase/result; it does not re-execute or load an old binding. Return `{workspace: current DataWorkspaceInfo, lookup:known|notFound|historical}`. workspace may be unavailable while an existing durable result remains readable. NotFound, old Unknown and historical Unknown never mean safe to resubmit. No engine initialization, secret access or state mutation occurs in this query.

### Qualified historical resolution across namespaces

Each written view stores a protected capture vector by placement/binding anchor. Local unpinned references resolve against the view's own requested commit for historical reads (the self-commit is a resolution rule, not a circular stored hash). Foreign unpinned targets capture exact `(targetNamespace,targetCommit,targetId,targetRevision)` at publication; those commits are verified by the controller under deterministic namespace-lock order and current ACL. There is a coherent observed capture vector under cooperative Core ownership, not a distributed atomic transaction across files. Current live rendering follows current target heads; historical rendering uses the stored vector and NEVER today's foreign HEAD. Explicit pinned refs always use their exact qualified target commit. Missing/corrupt captures remain unavailable/incomplete; no implicit latest fallback.

If a preserved inaccessible Keep cannot lawfully observe a fresh foreign head, the previous capture is retained without reading that workspace. A later historical render stays on that retained version or explicit unavailable state. New inaccessible foreign refs are refused. The same rules apply to typed Object code bindings. Free query bindings access only the current namespace's user tables; there is no cross-file ATTACH or implicit cross-namespace SQL join. Provenance refs and relations are qualified links, not authority to dereference another scope.

### Output redaction is in the actual value, not a side table

All OUTPUT reference-bearing fields use `DataRefState`: visible includes the authorized DataRef; unavailable contains no namespace/id/title/pin/revision/count or reason distinguishing denial from missing. This applies directly to DataPlacement.block, Object binding targets, relation subject/object and provenance sources, as well as detail.references. An unavailable placement still has its own stable placement ID and author-owned layout; its atCommit is null. Its resolved reference entry has commit/revision=null and complete=false. Code binding Keep and placement Keep preserve the hidden raw pointer server-side without exposing it. The API never returns raw protected object JSON/diff as a workaround; typed diff/export projections apply the same policy. Source/schema/user-code strings are author-authored data, not automatically dereferenced private labels and not scanned to invent access authority.

Direct object reads first authorize workspace scope, then may report missing within that authorized namespace. Referenced unavailable targets unify denied/missing/unreadable in the render projection. The client must show Unavailable/Incomplete, not infer existence from Denied versus Missing. A view does not acquire the block's rights. Revocation is rechecked before delivery; historical content does not bypass current scope permissions.
