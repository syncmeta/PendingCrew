# Core personal draft transport — complete consumer contract

This independent module extends the existing personal Draft/branch owner with one optional Core transport. It does not replace that owner, promise CloudKit qualification, synchronize business databases, or send/restore a task. The original local/Cloud files remain separate projections. Exactly one current destination is selected: local, this verified Core private space, or private Cloud. Switching preserves old latest/recovered/receipt/exit gates; no automatic import, migration, relay or dual write. This is a typed consumer contract, not complete backend/GUI acceptance.

Canonical types: crewd/crates/proto/src/personal_drafts.rs. Added direct methods are personalDraft.status, personalDraft.members, personalDraft.catalog, personalDraft.branches, personalDraft.requestFence. The first four return bare typed read objects. requestFence is a durable CONTROL WRITE with its own typed bare result, not a read or a retry. Five new PublicCommand variants use existing command.submit and command.lookup, never a second journal. API remains3; with accepted Claude A144, the new method count is149. Store21 is the necessary writer barrier proven by an exact old20 restore counterexample. Fresh21 and protected20→21 initialize a private Draft restore stamp; experimental Native16 remains unavailable. No new hello flag is inferred: a typed status result establishes only this API surface; availability/explicit consent/current authority still govern use.

## Identity and explicit private membership

Content key: {authorityId,dbId,crewId,destination:{kind:"channel"|"originalSession",id},kind:"channelMessage"|"sessionMessage"|"initialTask"}. The current SQLite content authorityId equals its actual dbId. channelMessage/initialTask require a real channel in that crew; sessionMessage requires the exact original PCW session in that crew. Names, transport authority, runtime binding, remote record UUID and grant revisions are not content identity. All current original crew/destination visibility gates still apply. Mention/reply values are inert; they grant no access or execution.

Synchronization scope: {spaceId,spaceEpoch,memberId,memberRevision}. IDs/writers are Core-minted stable canonical UUIDs; revisions/cuts are canonical nonnegative decimal strings (positive where stated). spaceEpoch is an opaque restore-context fence, never a device ID. Every network operation captures current verified transport authority/db/pin/grant/revision/connection in addition to this scope. spaceRevision/memberRevision are operation CAS/await fences, never namespace keys; stable spaceId/spaceEpoch/memberId/writerId define a projection. No client-supplied writer, Apple ID, same crew, same Core, display label or matching certificate product signature establishes common ownership.

Only existing real Local Human or the true-rootFD typed host-admin owner may create/manage the single current private space and approve an exact existing live grant+current revision+client SPKI. Ordinary remote paired devices cannot add themselves/other devices or manage membership. B links are unchanged. Each approved grant gets a fresh memberId and writerId with optedIn=false; that device must explicitly enable its consent. Re-pair/re-approval does not inherit an old writer, branches or consent. Owner removal and original grant revocation immediately block subsequent reads/writes/events. No claim that cached local text is remotely erased.

A genuine Local Human can explicitly enable one Core-owned local member/writer; multiple windows share the existing single personal draft service. rootFD only manages members, never pretends to be a local App draft writer. All Agent entry paths deny before any private data read. Plain same UID or JSON role never manufactures an owner. No new login, account, OAuth, private key copy, shared grant or enrollment parameter.

## Status, ownership and consent

personalDraft.status {} -> PersonalDraftStatus, bare:
{dbId,owner,ownerEpoch,available,reason,spaceId,spaceEpoch,spaceRevision,member,payloadLimitBytes,spaceLimitBytes,branchLimit,memberLimit}.
ownerEpoch is the current opaque original Core restore epoch for a real owner, null for remote members; it also binds first configuration before a space exists. Nullable fields are explicitly null. member is PersonalDraftMember or null. owner is actual management authority, not remote membership. available requires current membership, opt-in, restore epoch and live original authorization; method success alone is not availability. Stable reason codes: notConfigured, notApproved, optedOut, restoreRequired (or null when available). An unapproved paired device receives no other member, private space/writer, payload or branch identity.

PersonalDraftMember: {memberId,writerId,revision,grantId,grantRevision,clientSpkiSha256,optedIn,revoked}; local member has null grant fields. Server returns its exact revision; clients do not invent or increment membership revisions.

personalDraft.members {spaceId,spaceEpoch} -> {spaceId,spaceEpoch,revision,members:[PersonalDraftMember]}, bare, real owner only. Max64 total members including revoked entries; no unbounded account directory. Owner uses current spaceRevision CAS.

All five writes below use existing CommandSubmitParams {requestId,dbId,runtimeBindingId,command:{operation,params}} and return the existing PublicCommandReceipt directly. SQL success phase is committed, with result PersonalDraftMutationResult:
{operation,spaceId,spaceEpoch,spaceRevision,member:null|PersonalDraftMember,branch:null|PersonalDraftBranch,retired:[{branchId,revision}]}.
No new dispatched/provider phase, model or physical task is involved. Existing/historical receipts retain their original identity; only current source authorization permits disclosure.

- personalDraft.ownerConfigure {ownerEpoch,expectedSpaceId:null|id,expectedSpaceRevision,localEnabled,acknowledgeRestore}: owner-only, and ownerEpoch must equal the actual current Core restore epoch in the owning transaction. First exact null/0 creates the one current space. localEnabled explicitly controls only the real Local Human member; true-rootFD must use false. After restore, acknowledgeRestore=true is required to create a new empty current space/epoch; original archived space bytes are retained, not implicitly imported or made writable.
- personalDraft.memberSet {spaceId,spaceEpoch,expectedSpaceRevision,grantId,grantRevision,clientSpkiSha256,enabled}: owner-only. enabled=true approves the exact currently live grant and creates a new writer with consent off. An already approved live grant conflicts; it is not a way to refresh/steal its writer. enabled=false removes that exact approved membership, increments its revision, clears consent and permanently revokes that member. Original remote grant remains independently governed by B.
- personalDraft.consentSet {scope,enabled}: only the actual approved device/local writer, current exact membership CAS. Returns new member revision. Disabling does not delete cached/server branches. Enabling needs a new explicit user decision; selection/connection alone never enables it. spaceRevision/memberRevision fence operations and awaits only: they never create another local namespace. Stable spaceId/spaceEpoch/memberId/writerId establish the projection; re-approval or restore creates a genuinely different scope.
- personalDraft.checkpoint {scope,branchId,key,expectedRevision,revision,payload}: exact own writer only. A new branch requires expectedRevision="0", a never-used random branchId and no other active own branch for that key. Existing branch requires exact server revision, same key/writer, not retired and strictly greater incoming original checkpoint revision. Offline local checkpoints may skip numbers. No device can raise another writer's revision. Successful send-clear is a higher-revision empty typed payload under the same branch/CAS, not deletion of other devices' versions.
- personalDraft.resolve {scope,key,retiring:[{branchId,revision}],replacement:null|{branchId,revision,payload}}: explicit confirmed merge/retirement,1..64 distinct exact live branch/revision witnesses of that key. One transaction validates all witnesses, permanently retires precisely those rows and optionally creates a never-used new own branch. If replacement exists every active own branch of that key must be explicitly among retiring; no silent overwrite. Any changed revision rejects the entire mutation and preserves local merged text. resolve.result.retired returns the exact original witness revision, not an incremented tombstone revision. Tombstones keep original branch/key/writer/revision and null payload forever; ordinary checkpoint can never revive one.

Local/server payload is the existing full Draft v1:
{text,stagedMentions:[{token,mention:{kind,target_id:null|string}}],replyTarget:null|{mention:null|{kind,target_id:null|string},replyToId,quotedSender,quotedSnippet}}.
Preserve exact original strings, mentions and reply data. No media, upload/prepared input references, path/bookmark/token or executable capability field is accepted. Draft restoration never executes mentions or sends a reply. The original send path rechecks all permissions/references when the Human actually sends.

Linux uses the same store/receipt transactions through existing typed rootFD owner operations: host.personalDraftOwnerConfigure and host.personalDraftMemberSet accept {requestId,dbId,runtimeBindingId,params:<exact above>}; host.personalDraftStatus {} -> {runtimeBindingId,status:<PersonalDraftStatus>} supplies the actual current receipt-binding source without a generic host hello/RPC. host.personalDraftMembers {spaceId,spaceEpoch}, host.personalDraftRequestLookup {requestId,dbId} provide owner status/read/original receipt only. host.personalDraftRequestFence takes the same full original envelope and returns the same three-state fence result, but its only root-admin whitelist is ownerConfigure/memberSet under that same real root-admin identity. No generic command/RPC proxy, new socket, bearer, same-UID elevation or fake LocalHuman. Root requests have their own authenticated root-admin principal namespace; remote/App do not consume the rootFD protocol.

The existing Linux `pendingcrew-host` CLI exposes `draft-status`, `draft-members --space-id … --space-epoch …`, `draft-control --kind owner|member --operation-file <owned0600>`, `draft-lookup --request-id …` and `draft-fence --request-id …`. `draft-status` supplies the actual DB/runtime binding and private owner epoch. The operation file is exactly `{requestId,dbId,runtimeBindingId,params}` from that source; root owner params must set localEnabled=false. Before the one control RPC the CLI preserves the full original control envelope and digest in its existing root-owned operation store. Response loss stops; lookup or the durable negative fence uses only that original record. A missing lookup alone never resubmits. These commands do not create a service, install packages, enable a transport or grant a local writer.

## Bounded reads, events and branch convergence

personalDraft.catalog {scope,cursor:null|opaque,limit:1..64} -> {scope,entries:[{key,activeBranches,retiredBranches}],membershipCut,nextCursor:null|opaque,complete,observedAt}.
personalDraft.branches {scope,key,cursor:null|opaque,limit:1..64} -> {scope,branches:[PersonalDraftBranch],membershipCut,nextCursor:null|opaque,complete,observedAt}.
Limits default32. Branch shape: {branchId,key,writerId,revision,retired,payload:null|Draft}. Active rows have full payload, tombstones have null. Both APIs check current membership/consent and source/destination ACL at read/disclosure; an unauthorized key cannot be used as a private draft oracle.

Cursor binds exact space/epoch/member/revision, optional key and immutable last-row identity plus maximum branch insertion sequence. It freezes membership/order only, not mutable status. Current revisions/tombstones may be newer on later pages and are labeled observedAt. No snapshot/version ledger. A changed restore/member/source/cursor rejects; client explicitly restarts a read, never a write. A partial page is not a complete exchange, absence does not imply deletion, and a stopped exchange cannot mark all branches synchronized. Existing merge gives a tombstone priority over any active version. Local originals behind a tombstone enter the existing recovered/export path; no automatic new-branch minting to evade retirement.

The original events.subscribe topic personalDraft carries personalDraft.changed {spaceId,spaceEpoch,revision} only after durable mutation. It contains no payload, key, grant or device name. Original forwarder checks current membership/consent and epoch immediately before forwarding and always denies attached Agents. Lag/reconnect means explicit bounded read/merge through the original foreground single-inflight owner; event hints grant no authority and never start sessions. No new scheduler, background retry loop, polling daemon or second bus.

Bounds:64KiB encoded full payload,64 staged mentions,8MiB serialized active-space state,4096 branches including tombstones,64 members including revoked. Archived restore spaces are retained under a64MiB Core metadata cap/max64 spaces; no auto-GC. Public command256KiB and original16MiB frame limits still apply. Capacity refusal keeps the last durable originals and all receipts/tombstones; local latest/recovered/export and quit protection continue. No per-keystroke server history is added.

## Unknown, original receipt and negative fence

Unknown is scoped to the original branch network mutation, original UUID/envelope and source. It never blocks unrelated settings/history or local text checkpoints. command.lookup {requestId,dbId} returns the original existing receipt or null and never mutates. A fresh branch list is not a receipt; null alone is not proof of non-submission. No automatic resubmit, new UUID, re-upload or old-body replay follows an uncertain result.

personalDraft.requestFence {original:<FULL original CommandSubmitParams>} -> {state:"existingTerminal"|"existingPending"|"missingFenced",receipt:<PublicCommandReceipt>} is a durable negative control write. Its only whitelist is the five SQL-only commands of this module, never sessions/models/files, arbitrary SQL or other public commands. It takes no new UUID and reserves no second command ledger. The exact actor/principal, original DB, epoch, membership/writer grant, branch/key and canonical original envelope hash are validated inside the original DB owner. It must still have current authorization for that original scope; revocation/restore/re-pair cannot be used to fence or disclose old text through a new identity.

Ordinary Core process restart does not change a space/restore epoch or member/writer. Original UUID lookup/fence may finish across runtime bindings under the same actual source and current authority; original runtimeBindingId remains immutable in the original envelope/hash and is never replaced to force retransmission. Actual restore changes the real original restore context; old scope/ownerEpoch controls remain historical in their old gate and cannot block a new explicitly acknowledged restore-space operation. Owner/consent controls scope their Unknown gate by original ownerEpoch/space/member, not globally across all settings.

The fence and original submission use the same transaction/primary key: exact Existing only returns its original receipt without executing; a different immutable envelope conflicts. Existing nonterminal returns existingPending and keeps the gate. Missing reserves that exact original envelope/UUID and immediately transitions it to terminal rejected with result {reason:"notSubmitted"} in the same transaction. A later/previously captured old submit must perform its final reserve/Existing execution check in that same transaction, and therefore cannot run after the negative fence. No mutation or provider effect is retried. This race is a required actual original seam, including capture-before-FIFO and both transaction orders.

Only committed or terminal rejected/suppressed receipts, including missingFenced, close that original network gate. Historical successes cannot be projected as current synchronization; unknown/pending remain unknown/pending, never promoted. A negative terminal closes only that exact original packet, and creates no positive synchronization fact. Client retains original local text/version/UUID; closing a gate never re-sends the old packet or mints a new UUID to replay its body. A genuinely newer local checkpoint or explicit Human save of a new version may continue under the current CAS/opt-in policy even if its body is identical; no arbitrary text edit is required. Fenced means the original packet did not submit, never that the draft is synchronized. Owner/consent management uses this same narrowly whitelisted negative fence and the same original receipt identity; it never blocks unrelated branch editing. App ownerConfigure is also bound to ownerEpoch before any space exists. Root-admin uses only its typed equivalent for ownerConfigure/memberSet, never a generic command proxy.

## Restore and evidence boundaries

All space/member/branch state is optional versioned private metadata in the existing protected SQLite backup/restore boundary, not a new database, command ledger or execution authority. Every space binds the private persisted personalDraft.restoreStamp.v1. The stamp is created in the original protected initialization/migration transaction, remains stable across ordinary process restart and remote configuration CAS, and rotates only in the original restore staging transaction. It exists before any private space and supplies ownerEpoch to the true owner. Judgment configuration and its witness domain are unchanged. Accurate old20 restore preserved the former stamp and revived an old opted-in writer, including a late successful checkpoint; Store21 therefore rejects that old writer at the original source and destination version guards. Current restore preserves archived bytes but invalidates old memberships and write scopes. Owner acknowledgment creates a distinct empty current space/epoch with fresh memberships/writers and consent off. Old local namespace originals and archived server bytes stay preserved; no automatic copy or reassociation. Old receipts remain historical and cannot prove a current checkpoint; old grant/key, scope or branch cursor cannot enter the new space. A new same-looking pairing never inherits an old member. The affected exact old20 and current21 source/destination, protected migration, restore, ordinary restart and remote-CAS seams establish this boundary; no historical compatibility or separate recovery framework is introduced.

Source/backend tests, final independent acceptance, Mac/VPS real management/data plane, actual multi-device/offline/revoke workflow and Cloud/Apple device qualification are separate. No real provider/SDK/model, Cloud/Keychain, Apple secret, public listener, VPS, CI, package or normal witness is authorized by this contract preparation.
