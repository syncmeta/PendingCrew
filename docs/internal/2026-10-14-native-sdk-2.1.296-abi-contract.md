## Full history, not a4096-row substitute

A complete ACP replay projection needs native stored-row UUID/content/provenance, immutable source/build/session association, contiguous durable sequence and an explicit coverage origin. It is a transcript projection, not a second WorkBook or command-effect ledger. New native sessions may establish a verified empty origin before the first append, then keep every authenticated returned append row. Disconnect/crash/persistence failure marks a gap; a newest4096 window cannot repair it by assumption.

For an old/resumed/imported session, full coverage requires a separately verified native transcript snapshot and its parent/fork/compaction ancestry, with owned in-scope path/inode/birth, stable read/cut and native session identity checks. The SDK's classic transcript path is a discovery lead, not proof that a parser understands the current file or that the snapshot is complete. Until a full importer is proven, old/unknown history is an explicit incomplete-history refusal; this is a remaining M4 delivery requirement, not an accepted substitute.

Replay reads the complete durable projection and emits ordered ACP `session/update` user/assistant/tool-call/tool-result updates before the `session/load` response. Every supported block is mapped without loss. Unknown or oversized blocks mark coverage incomplete and refuse load rather than discard them. Snapshot/cut/continuing-append races require an immutable replay high-water plus subsequent updates. A terminal screen is never transcript replay authority.

The existing frozen12 finite execution receipt rows cannot carry this history. Public14's approved single command/manual-control projections also must not be silently repurposed. Proposed durable transcript coverage/row projection therefore needs a separate explicit version decision (prospective15 after14), with protected migration, restore/import coverage invalidation and rollback gates.
