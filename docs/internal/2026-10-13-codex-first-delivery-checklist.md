# Codex 首版本机交付清单

当前交付目标按全工程计划M1/M2/M3执行：完成工作与恢复闭环、原微信式完整本机工作台，再交付可持续自用的Codex版本。文档及四视图独立文件夹属于此次交付前置，不能用旧薄首版清单排除。行政调度、Claude真实PTY/ACP及其他平台仍是后续全工程范围；Jev/记忆先讨论。此清单用于冻结和交接，不替代运行验收。

## 当前版本的交付关口

1. 后端线冻结M1工作/恢复与M2文档/分类的完整生产版本；客户端线冻结同契约的全部可操作界面及构建脚本；质量线完成组合验收。没有M2真实接口不得以禁用按钮或占位页面通过。
2. 根核对精确源码ref、main/远端祖先关系、变更所有权及未提交人类资料，整合已验收版本。构建从不可变源码snapshot开始，记录GUI与Rust的实际输入manifest及产物hash。仅写一个sourceRef或在结束时读取HEAD不足以证明来源。
3. 以同一冻结helper完成合成客户端、停止与恢复、优雅/强制重启及文档/分类持久性验收。旧版本的日志不代替当前产物；不得擅自另外编译debug helper后宣称测过包内helper。
4. 当前版本完成实际可见窗口操作与既有授权范围内真实Codex任务。权限等待只阻断相应动作，其他交付工作继续；离屏渲染不代替可见窗口，旧候选真实任务不代替当前版本。
5. 验证历史库升级、备份与失败回退，再分别执行授权范围内的安装/切换。新库经过升级后不得让旧二进制直接写入；回退使用保留的旧应用与升级前备份副本，不覆盖用户现有数据或删除新版本产生的记录。明确回退期间两份数据的归属。
6. 用交付版本完成后续实际开发单元，检查通信、人工答复、交接、恢复及结果留存，形成持续自用证据。完成此关口后继续M4/M5/M6，不能宣称整个工程结束。

当前缺口：M2模块与窗口操作、固定snapshot构建脚本、最终一致版本、当前真实任务、安装/真实数据切换均未完成。构建来源审计方案不是已经改完构建脚本。

## 冻结产物

选择且只指定一个交付应用目录及其 `source-head.txt`。保留同目录空 `source-changes.patch`、`artifact-sha256.txt` 与原始验收日志。执行：

```sh
sh scripts/dev/check-codex-first-artifact.sh '/absolute/path/PendingCrew Codex First.app'
```

脚本只读检查 plist、GUI/helper 可执行文件、两层签名、源码记录和实际 hash；不会启动后台、模型或读取登录凭据。搬迁产物时应用和三个 metadata 文件须一起保留。通过只证明产物与记录一致，不证明 Git SHA 构建来源、正式签名/公证、安装或真实运行；冻结构建仍须保留对应构建日志。

## 交给用户前写清

- 实际应用路径、冻结 SHA、macOS 14+ 和已安装/登录的 Codex CLI。自动发现 `~/.local/bin/codex`、`/opt/homebrew/bin/codex`、`/usr/local/bin/codex`；其他路径显式使用 `PENDINGCREW_CODEX_PROGRAM`。
- 默认独立根 `~/Library/Application Support/PendingCrewNext`，可用 `PENDINGCREW_CREWD_DATA_DIR` 指定；不与旧根共用，不自动导入旧库。启动前确认该根已有实例和数据归属。
- 打开首版后建机组、选工作目录、交代初始任务；后续群消息通知选中成员。错误显示在窗口，后台日志在 `<独立根>/client-backend.log`。
- 退出窗口不等于停止后台/成员。先在窗口停止成员；需要退出后台时核对对应数据根和自有 PID，通过已有 crewd 控制入口操作，不使用广泛 kill 命令。后台重启后人工选择恢复/暂缓，核对中断工作的实际结果。
- 旧应用与旧数据继续保留。此次完整本机版本须实际提供原微信式通讯录/消息与消息/Todo/文档/进展；原型、旧操作窗口或禁用占位不能代替完成。

安装、正式发布、日常数据切换与追加真实付费任务按既有授权分别执行。可先完成构建、合成验收和交接材料，再提出具体可审阅的授权动作。实际安装/迁移未验收时明确写“未完成”，不由源码测试推断。
