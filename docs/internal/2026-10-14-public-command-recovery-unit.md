# Reliable public commands, receipts and terminal recovery unit

Status: the root approved this whole public request/terminal recovery unit for implementation after the current M5 closure. This is one complete public request/recovery unit, independent of M5 facts and of still-unknown real native SDK/history/approval evidence. It must not alter frozen schema12 or reuse a frozen13 followup migration. Approved activation version14 follows13 in order and installs only public-command/manual-control projections; WorkBook, crews/messages/session authority and the real executor remain their respective authorities.

## Preserve existing contracts

`document`, `folder`, work creation and remote configuration/pairing operations already have specific accepted request identity/CAS contracts. Preserve them and their actual evidence. Today's `crew.create`, `message.post` and `session.start` have no common public request ID/lookup contract; private native_execution receipts and a frontend-generated UUID do not create one. The present client must retain single submission, original-scope unknown snapshots and explicit Human confirmation/readback. Client presentation journals are not server success ledgers or retry outboxes.

Local `remote.status` can return an actual optional remote authority/db public identity without creating it or binding a listener. An absent identity remains unconfirmed. Remote presentation records can bind their already verified pairRecord/authority/db/grant/revision. A local data-dir/display namespace is a presentation locator, not authenticated DB identity.

## Version14 projection and identity

A `public_command_receipts` row has a canonical request UUID, authenticated owner principal, original server/work identity and scope, fixed allowed operation, exact bounded canonical payload bytes/hash, phase, immutable resulting object IDs/response and bounded failure disposition. The unique key is authenticated owner+request UUID. A duplicate with another operation/scope/payload is a typed conflict before effects. Receipt authority never derives from client-supplied actor, PID, installation UUID or crew currently selected in the UI.

Authentication assigns the principal from local Human IPC peer policy or an already paired remote identity. Registered agents cannot claim Human access. Remote grant and current original-scope permission are rechecked for submission and lookup. Readback after reconnect requires the same actual identity and retained original scope; losing permission or trust fails closed. Restore/import/generation replacement invalidate copied execution/manual admission, retain historical request attribution and classify uncertain external effects conservatively. A server snapshot cannot promise exactly-once across unobservable rollback.

## Proposed strict public surface

`command.submit({requestId,operation,params})` supports a closed typed whitelist, initially `crew.create`, typed `crew.createFirstMessage`, `message.post`, `session.start`, `session.stop`, `session.resume`, `session.interrupt`, `session.answer`, `session.respondRunnerRequest` and the terminal operations detailed in `2026-10-14-m4-public-terminal-contract.md`. Other commands retain their existing specific contracts rather than passing arbitrary RPC names through a generic executor. Exact wire schema, method constants, permission map and normal dispatcher freeze together.

`command.lookup({requestId})` is read-only and returns the stored original scope/operation/hash, a typed phase, immutable output IDs when confirmed and a safe reason when uncertain. It never resubmits a command. Optional bounded `command.listUnknown` lists only that same authenticated principal's records in the requested original scope; it must not reveal foreign requests by guessed UUID. Client local prepared records may exist without a server row. “Not found” alone cannot establish that an earlier write did not happen; a caller keeps the original unknown record and asks for Human reconciliation.

Proposed phases distinguish `prepared`, `committed` (transactional authority including its receipt), `dispatched` (external execution admitted), `unknown` (physical result unconfirmed), `suppressed` and `rejected`. A queued/accepted RPC ACK is not a business or physical success. Rejection is only reported if its authoritative transaction had no side effects. Stable typed errors distinguish mismatched payload, stale server/generation, foreign principal/scope, grant/trust revoked and unavailable executor/native controls.

A source-safe first-message path should use one typed `crew.createFirstMessage` command if it must atomically create a new crew and its initial message. SQL crew/message/receipt writes share a single Core transaction, and object IDs are resolved by Core in that new crew. It must not implement frontend create→post rollback or post an old draft into a newly selected crew. Any optional session execution that follows is a separately recorded external lifecycle, not part of an imaginary SQL/OS atomic transaction. The root selected this composite route; optional session start receives its own receipt and external lifecycle.

## Execution and recovery

For transactional operations, authoritative mutation, object identity, receipt result and emitted change set commit together. Unknown socket outcome can be queried by exact original request ID; repeated `submit` only reports the saved result and never invokes mutation again. For `session.start`, persist the scoped prepared command and reserved session identity before external work. The production orchestra accepts that exact command identity once; claim/dispatch/physical launch/result and generation settle separately. Crash after launch but before acknowledgement becomes unknown, with actual registry/custody recovery obligations. It must not simply start a second provider because a receipt is absent or a connection restarted.

Terminal input/resize uses the same public request identity but its actual lease/runtime/manual revocation authority remains in the executor-control projection. Human custody, durable raw revocation before bytes, actual exact kernel-accepted bytes/resize acknowledgement, unknown write no replay, bounded observation and cleanup are complete-module obligations, not inferred from `command.submit` being parsed.

Frontend prepared state is durable before potential write, scoped to the real observed server/pair binding and crew/operation. An ACK can annotate accepted metadata, but the server authority/result remains the source of truth. Restart/connection/device change retains original scope and request identity; clients perform explicit read-only lookup and present the result. They never automatically replay a prepared/unknown draft, retarget it to another crew/server or clear records because source/configuration changed.

Freeze source/schema/normal capability only after real public authenticated IPC/paired handlers, transactional mutations, async start admission, terminal custody and recovery are connected. Verify before-write crash, after-write/lost ACK, identical duplicate, mismatched payload, foreign principal/scope, revoked permissions, reconnect/device identity, bounded request storage/lookup, composite SQL rollback, physical start unknown/reaping and no second provider, manual input unknown/no replay, Stop, restart/restore/import and snapshot rollback limits. Independent quality validates real complete user flows with temporary fake providers and immutable normal input/config/binary proof. ## Approved complete lifecycle refinements

The typed terminal methods and whitelisted `command.submit` share one `public_command_receipts` implementation and the same scheduler/custody path; do not create independent input/command receipt ledgers. Normal terminal writes return exact `written`/`acceptedByPty` byte counts only. Without an authenticated native reader ACK, they cannot report `consumed`. Partial/interrupted writes become unknown and never trigger a replay of remaining bytes. TUI output cannot upgrade them to successful command execution.

External phases explicitly separate `reserved`, `admitted`, `dispatched`, actual `launched`/`written`/`resized`, confirmed result and `unknown`; SQL `committed` means only the atomically committed SQL facts. Core reserves session/control identity and binds actual child birth/generation. Manual or remote revocation must be durably acknowledged before permission to issue bytes; in-flight outcomes and physical cleanup are still separate obligations.

Stop records Human stop intent/floor and receipt atomically before physical settlement. Repeat request IDs read that same obligation and never add a second stop/restart dispatch. Resume is an explicit Human command bound to the original stopped state/scope; its prepared/unknown result never automatically enqueues another resume or changes the monotonic stop floor. Decisions pin actual runtime generation and current decision/request fingerprint plus immutable response. Lost approval/write results stay unknown until authenticated state is available; a menu repaint or event/source string is not a receipted result. Unsupported genuine native decisions remain unavailable.

Receipt lookup authorizes the real paired principal or existing trusted local Human IPC policy before revealing existence, payload hash, scope or result. Frontend request UUID is solely a correlation key. Current grants/scope revocation and copied-backup attribution are respected. Backup rollback can preserve historical attribution but cannot promote an old external result into current completion; changed runtime/generation is explicit. Retention keeps unknown/active obligations and original scopes; settled data may be bounded only with tombstones/idempotency policy that cannot turn a pruned unknown into a new automatically replayable command.

All execution/approval commands, including `session.interrupt`, pin the actual original runtime generation and, where applicable, structured turn/runner request identity. Disconnect/replay of old Interrupt or Stop must never affect a replacement generation or a new turn under the same session ID. Duplicate receipt lookup never invokes the executor again. Formal answering requires an actual structured request; TUI text/fingerprint invention cannot authorize an approval. Resume establishes a physically new generation separately from retaining/settling older unknown obligations. Normal capabilities freeze only after this complete lifecycle surface is implemented and actually verified.

The wrapper permission never substitutes for the whitelisted operation permission. Submission invokes the original trusted actor/grant/method-group and crew/session scope checks for its typed inner operation. Lookup/listUnknown re-authorizes the stored original operation against current original scope/grant before revealing any receipt existence/hash/payload/result. Local trusted Human IPC and real paired remote principals remain distinct stored identities; agents are never promoted to Human. Existing specific resource requestId/CAS implementations are reused compatibly by the one receipt path, not rewritten or exposed through an arbitrary RPC proxy.
