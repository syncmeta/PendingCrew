## Complete useful unit

1. Trusted native input: images, audio, bounded UTF8 text files and explicit enabled skill selections, through original queue/steer and new-session first input. Preserve Human task bytes and separate attachment input elements. No arbitrary client path, remote URL, data URL or native fileId. The exported UserInput has localImage/localAudio/text/skill/mention, but no arbitrary binary document upload. Unsupported binary formats remain explicitly unavailable instead of a fake file-input promise. Workspace file mentions can be separately typed only when resolved under the original canonical workdir; they do not grant writable roots or become uploaded documents.
2. Native history management: explicit Human archive/unarchive/delete for a physically stopped original thread, and revert-before-turn for a running idle loaded paginated thread with no queued input or pending decision. Native thread/revert only truncates persisted conversation history; it does not revert files. No action starts/resumes a session. Unarchive does not run it. Delete preserves PCW work/receipts and tombstones only its native conversation binding, preventing future resume/fork/review/queue. All effects use one original command, current exact target and the existing per-session mutation owner; lost ACK remains Unknown and forbids replay or false resumed state.
3. Native named permission profiles: bounded permissionProfile/list for original cwd, closed selection of an advertised allowed profile through existing configure and new-session options. The actual native permissions selector is mutually exclusive with sandboxPolicy/sandbox. It does not edit a global config file, select arbitrary config keys, install a plugin, answer an approval, or raise Core permissions. Accepted next-turn settings remain distinct from observed-effective values.
4. Complete inspection: honest capability matrix including actual historyMode/native lifecycle/profile availability and attachment limits. The existing model/effort/fast/approval/plan/usage/history/name/task-first/steer/queue/stop paths are reused, not rewritten. Claude full history/load/manual lifecycle remain unavailable; APNs managed observations do not confer that capability.

## Proposed minimal typed additions

- Read-only session.codex.permissionProfiles {sessionId,cursor?,limit?} -> {items:[{id,allowed,description?}],nextCursor?}, fixed original cwd, limit1..100.
- session.codex.inputPrepare is a narrow typed staging RPC with original requestId, crewId, optional existing sessionId, display filename, closed kind(image/audio/text), SHA256 and base64 bytes. Single bounded upload <=4MiB (text <=512KiB), below the existing16MiB RPC frame, no chunk service. The existing public command envelope is only256KiB, so it is not enlarged to carry media. Result is source/owner-bound opaque inputId + digest/kind/size; it does not deliver a task. Narrow read-only session.codex.inputLookup {crewId,requestId} returns only the original owned staging result; Unknown never uploads again. A prepared new-session input is crew/actor-bound and becomes bound to the new Core row in the original session.start transaction before dispatch. Existing message.post attachments remain refused (prior ruling14).
- Existing CodexQueue/CodexSteer/CodexTextParams gain omitted optional input refs and enabled-skill selections (<=16 elements, aggregate bound). Original text is unchanged and original exact turn required for steer. New-session options gain a separate optional initial input selection, preserving absent-field receipt equality. No appended file text is hidden inside the Human task string.
- Public commands session.codex.archive/unarchive/delete/revert, original target; revert includes beforeTurnId. A shared typed native-history result records exact operation/thread and provider ACK. History Unknown records block future native mutation/resume as appropriate. Five parallel metadata reads remain usable; no global lock or new scheduler.
- Existing CodexSettingsPatch gains omitted permissions selection, mutually exclusive with sandbox. Catalog ID and allowed status must be verified for the actual original cwd before final provider write under the original lease; changed/stale/unknown catalog refuses rather than executing arbitrary profile input.

These are proposed names before the single contract decision, not frozen DTOs. Native schema methods are thread/archive, thread/unarchive, thread/delete, thread/revert, permissionProfile/list. ThreadStartParams.historyMode exists; new threads can use paginated explicitly, existing legacy mode is never silently converted. Revert on legacy/unloaded state is unavailable unless a future supported upstream contract proves otherwise.

## Persistence and old writer boundary

No second knowledge/content authority or upload server. Native-input bytes belong to this original Core/session/input request, bounded in a small private SQLite attachment table, covered by original database backup/restore. Enforce64MiB/session and256MiB/Core staging quotas; no automatic materialization or execution on lookup/restart. A narrow explicit discard for unused staging is part of this same input lifecycle, preserving its original result witness; consumed/Unknown delivery records are not overwritten. Trusted materialization is a0700 owner directory/0600 regular immutable file keyed by UUID+digest, never client filename as a path, never symlink/overwrite or new writable root. Images/audio use native local input variants; text files become separate typed text elements with explicit source label. Client selection cannot resolve arbitrary server files. Per-actor/crew/session ownership and current authority are checked again at dispatch, so a new pairing cannot consume another grant's staged input.

Existing codex_controls::State uses deny_unknown_fields and exact version1; existing Core resume calls codex_resume_ready and codex_launch_options before dispatch. Prefer an explicit per-session metadata version2 only when the new native lifecycle capability is used: old writer then rejects that session instead of losing its tombstone/Unknown. Keep ordinary version1 rows byte-compatible, not a new global Store version merely for extra commands. Final implementation must prove the exact saved old19 writer fails closed before spawn and preserves v2 metadata/input bytes. If an original old19 path bypasses this barrier or backup/restore destroys authority, report that concrete evidence before requesting a Store20 barrier. No compatibility fallback, generic migration chain or Native16 activation.

Original per-session metadata mutation owner serializes title/fork/history writes and preserves request-id cleanup; Stop/hibernate/generation revoke the existing manual write permit. Revert uses a live idle handle; metadata-only children add only the three stopped history methods and profile catalog read, never resume/turn/login/config. Querying result never repeats delete/revert/input dispatch. No local filesystem rollback, provider private DB edit or inferred provider success.
