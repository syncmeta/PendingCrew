# 手工验收 · 终端手感三条（P1 交付，攒到下次装包时点）

> **不要为了点这几条专门装一次新版。** 这三下必须装新版才能验，而装新版要 ⌘Q、
> 所有在跑的 session 一起死 —— 那正是本项目要消灭的痛点，为验证它而制造它是本末倒置。
> **攒着**：等下一次本来就要装包的时候（P3 完成、或期间有别的原因要发版）一起点。
>
> P1 全部在 app 单进程内、可单 commit revert；数据层一致性（缓冲区语义 / reflow /
> alt-screen / 回滚长度）已被自动化覆盖（`TerminalMirrorParityTests`、
> `TerminalScrollbackTests`、`TerminatedScrollbackTests`）。人手这几下验的是**交互层手感**，
> 晚几天验、真出问题也 revert 得掉。

**这一阶段改了什么**：终端从「一个 AppKit 视图对象同时管 PTY + 屏幕 + 渲染 + 状态扫描」
劈成了**无画面内核**（进程 + 权威缓冲区 + 全部扫描器）与**只负责画的镜像视图**（吃字节流）。
两侧各有一份终端缓冲区、喂同一批字节。人的键盘/粘贴/鼠标现在先到镜像视图、再交给内核写进 PTY。
**唯一有意的行为变化**：机长 `inspect_session` 读的是内核那份权威画面，不再随你手动上滚而变。

前置：装上含 P1 的新版本，随便起一个 claude session，让它跑到吐出至少两屏输出。

---

## 0. 前置自检 —— 输入这条路还通吗（30 秒）

**做**：在终端里打一句话（含中文）按回车让它跑；再复制一段多行文本，⌘V 粘进去。

**判据（全部满足才算过）**：
- 打的字**立刻**出现在 claude 的输入框里，没有丢字、没有重复字符
- 中文输入法的候选/上屏正常，不出现半个字
- ⌘V 粘的多行文本**整段作为一条**进输入框（不是每一行各自提交一次）
- 回车提交后 claude 真的开始跑（不是把 `/` 开头的内容当字面文本吞掉）

> 为什么单列这条：P1 之后键盘字节的路径变了（视图 → 内核 → PTY），
> 而「粘贴 vs 敲键」是 claude 按字节到达时序判定的。这条不过，后面三条不用看了。

## 1. 改窗口宽度的重排

**做**：把 PendingCrew 窗口从当前宽度拖到约两倍宽，再拖回来。让 claude **正在跑**的时候
也拖一次（agent TUI 跑起来时是全屏 alt-screen，那是另一条代码路径）。

**判据（全部满足才算过）**：
- 历史整齐重排，没有半截行、没有断在一半的中文字
- 原本一行的长命令，加宽后仍是一行（不是被切成两段拼起来的样子）
- claude 跑着时拖宽/拖窄，它的 TUI 边框盒仍是完整的方框，没有断裂的竖线、没有右边框换行落到空行
- 拖动过程不卡顿到肉眼可见掉帧

## 2. 往上滚（回滚缓冲）

**做**：在终端里用触控板/滚轮一直往上滚，滚到不能再滚为止。

**判据**：
- 能滚回去的历史远超一屏（这个 session 跑过的输出基本都在）
- **最顶上那一行是完整的一行**，不是从半个字开始的碎片
- 滚动过程中右侧细滚动条跟着动，松手后自动淡出
- 滚到中间时 agent 继续吐字，画面**不会**被强行拽回底部（滚动条也不该一直闪）

## 3. 选中复制

**做**：用鼠标拖选一段**跨越至少三行**的文本（含中文和英文），⌘C，粘到任意文本框。

**判据**：
- 粘出来的内容与屏幕上选中的完全一致，行数、换行位置都对
- 中文不出现乱码或半个字
- 行尾没有多出一堆空格

---

## 4.（顺带）机长看到的画面不再跟着你滚

**做**：把某个 session 的终端**往上滚到历史中间**，然后让机长对这个 session
跑一次 `inspect_session`。

**判据**：
- 机长报回来的「终端画面」是**它当前真正卡在的那一屏**（贴底的最新画面），
  **不是**你正滚到的那一段历史
- 你把终端滚回底部，再让机长看一次 —— 两次读到的内容一致

> 这是 P1 唯一有意的行为变化（spec §5.1）。改动前机长读的是 SwiftTerm 的当前可见区，
> 于是「人往上滚，机长看到的文本就跟着变」。改完之后同一个 sessionId 在任何时刻问到的
> 都是同一份画面。
