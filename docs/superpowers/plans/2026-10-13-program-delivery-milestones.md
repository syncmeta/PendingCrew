## 并行所有权（本轮）

- 主代理：交付范围、依赖、版本冻结、跨线整合、最终验收与交付；不能把子代理测试通过直接当成整体验收。
- 客户端子代理：首版草稿隔离与定向回归；拥有 CrewdWorkspaceView.swift 和新增专用夹具/脚本，必要的构建源输入调整。保留用户原设计，不碰原型/其他聊天文件。
- 交付子代理：C1–C3 证据审计、只读候选校验脚本与交付清单；不启动账户或模型。
- 后端子代理：全工程依赖核查，提出第二阶段纵向单元；具体写入范围经主代理分配，避免与客户端和交付冲突。

共享 main 中用户 README 未提交内容及 ACP/设计未跟踪资料保留。实施在既有候选工作树；子代理提交只包含自己拥有的文件，不自行合 main、push、发布或切换真实数据。单一工作树上的提交、构建与整合串行协调，定向只读检查可并行。

## 验收与成本纪律

1. 每条线交付“结果 + 对应源码版本 + 有覆盖力的证据 + 剩余边界”，不堆测试数量。
2. 新缺陷先定向证明与修复；整合冻结后跑必要跨层门禁。相同源码和证据不重复完整审查。
3. 完整原始日志只保存一次，日常协作传短结果和路径；不让子代理重读全聊天、全 spec 历史或重复唤醒真实模型。
4. 原生权限、单一写者、停止与恢复、未知投递结果、数据耐久性是必需质量，不为缩短首版而削减。
5. 整体汇报列出里程碑、交付阻断、消除的阻断、下一关口。未证实的安装、日常数据、真机、真实跨厂商行为继续明确标出。

本计划是工作组织与验收约束，不宣称全工程已完成。详细后端依赖与首版核查由本轮子代理补充证据后整合。
